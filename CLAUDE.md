# 98ish: notes for the next session

A Windows 98-style web desktop at https://98ish.vercel.app. The owner uses it mostly on an iPhone and shares it with his girlfriend and friends.

## Layout
- **Client:** React 19 + Vite in `client/`, deployed by Vercel on every push to `main`.
  - Apps live in `client/src/components/applets/<app>/` and load lazily from `OS-specific/Desktop.jsx` (`lazyApp`).
  - Each app is registered in several places: `utils/programs.js` (fields `group` and optional `also: [...]` for Start menu folders, plus `online: "<id>"` for room games), `applets/dos/commands.js`, `applets/taskManager/processes.js`, `OS-specific/Helper.jsx` (Floppy tips), `utils/fs.js`, `utils/imageMapper.js`, an icon in `client/public/assets/program_icons/`, and a 98ish Help topic claiming it (`applets/help/topics/`; the help unit test fails without one).
- **Server:** `server.js` + `server/*` (Express, Socket.io, MongoDB), deployed by Render (service `srv-davi6cm7bikc73e5k5ig`) on every push.
  - Online games use the room system `server/arcade/rooms.js`, which has a guide at the top. Rules modules are in `server/arcade/games/`.
  - The client side of the room system is `client/src/components/shared/online/`.
- **Shared systems:**
  - **Audio** (`client/src/utils/audio.js`): one AudioContext and `createBus`, following the taskbar volume and mute.
  - **Draggable dialogs** (`shared/Dialog.jsx` + `hooks/useFloating.js`). During a drag the popup follows the pointer through left/top written once per frame from a containing-block origin measured at the press (which also re-reads where the box is drawn, so nothing that moved it can cause a jump); letting go measures and moves nothing (the older translate-then-commit release snapped the box elsewhere on a real iPhone, not reproducible in Chrome or Playwright WebKit). Ends on pointerup/pointercancel/lostpointercapture (never stuck). `?dragdebug=1` (remembered per browser; `=0` off) shows an on-screen log per release: drawn before -> after -> 300 ms later, plus refits. Phones: the title bar takes the gesture (`touch-action: none`, non-passive touchstart/touchmove preventDefault, no callout/selection, no long-press menu), a second finger can't take over, a finger's press never focuses a text field (it raised the 98ish keyboard mid-drag), and the whole popup stays inside the safe areas, above the taskbar and above the 98ish keyboard (it refits when `html.kb-open`/`--kb-h` change; the keyboard no longer `translate`-lifts `[data-floating=on]` boxes, which used to jump back when it hid). Mouse dragging is unchanged (60 px of title bar kept off-edge). Browser tests: `drag-phone.mjs` (CDP touch), `drag-webkit.mjs` (Playwright WebKit iPhone 14, iOS-ordered synthetic touch pointer events: `npx playwright-core install webkit`), `drag-desktop.mjs`; each checks no snap at release, a frame later and 300 ms later.
  - **Right-click menus** (`shared/ContextMenu.jsx`, rendered into `.os-root`) and the global right-click menu (`OS-specific/GlobalMenu.jsx`).
  - **Touch controls** (`shared/controls/`).
  - **98ish phone keyboard** (`shared/keyboard/`; design in `docs/keyboard.md`). Enter's label (`fields.js` `enterLabel`): the field's `enterKeyHint`, else search/url/multi-line, a dialog's default button (`data-kb-enter` from `Dialog.jsx`), Go in other forms, else Enter; never "Done" by itself. `enterKeyHint="next"` moves on without submitting. While it's up on a phone, window status bars hide (`data-kb-status="keep"` keeps one; YouTube's "Done" status read as part of the keyboard) and chat transcripts stay at the newest line. `data-kb-auto` + `requestKeyboard(el)` (`native.js`) bring it up with no tap (Speed Typist's race box at GO and when the race comes back into view). Browser scripts `kb2-*.mjs` (labels, chat/IM/Mail/dialog/game-chat layout, Speed Typist), sound on a phone `snd2-phone.mjs`.
  - **98-style drop-downs and date/time pickers** (`shared/select/`, `SelectHost` mounted once in App.jsx): takes over every `<select>` and `input[type=date|time|datetime-local|month]` with no change at the call sites. Touch: the tap's `touchend` is cancelled (no focus, so no iOS picker) and a 98 bottom sheet opens; mouse: the `mousedown` is cancelled and a list/calendar drops down (date fields keep typing; only their button opens the calendar); keys: Alt+Down/F4/Space. Choices go through the native value setter plus `input`/`change` events, so React state updates. Opt out with `data-native-select`; `multiple`/`size>1` lists stay native. Tests: `select.test.js`, browser scripts `sel-*.mjs`.
  - **98 Messenger calls** (1:1 voice/video, WebRTC): signaling in `server/aim/calls.js` (relays only between the two people in a call; busy, ring timeout, block, drop handling), ICE servers in `server/aim/ice.js`, client in `applets/aim/call/` (`engine.js` holds the call and the peer connection outside React; `CallManager.jsx` rings, opens windows, shows toasts; `CallWindow.jsx`, `RingWindow.jsx`). Calls start from the IM window header, a buddy's right-click menu, and Us ("Video call [partner]").
  - **Notification Center** (`utils/notifications.js`, taskbar bell `OS-specific/NotifyTray.jsx` + `Notify.css`, settings `NotifySettings.jsx` (lazy), `NotifyBridge.jsx` inside the Messenger provider): every toast (IMs, missed calls, Mail, Calendar, couples, game invitations, achievements, drive sync) also calls `notify({ app, title, text, key, target })`. Items merge by `key` (an IM and its push are one item), are kept per account in localStorage (`98ish.notifications`), and `target` is plain data (`{ kind: "im", with }`, `mail`, `calendar`, `program`, `invites`, `notifications`) that NotifyBridge opens. "Mark all read" / "Clear all" sync a `seenAt` per account to the server. Start > Settings > Notifications... opens the settings.
  - **Web Push** (`server/push/`, client `utils/push.js`, handlers at the end of `client/public/sw.js`): subscriptions per account and device, categories (im, calls, calendar, couples, mail, games), quiet hours (calls can ring through), 404/410 subscriptions deleted. A push goes out only when the person is away from 98ish: signed off, connection gone, or the tab hidden (the client sends `aim:visibility`). Triggers: IMs (IMs to someone signed off who has push on are kept and delivered at sign on; MongoDB collections `pushsubs`, `pushprefs`, `pushinboxes`), calls (a signed-off buddy with push still rings by notification; the ring reaches them if they open 98ish while it rings; missed calls), Mail, game invitations, couple notices (letters, flowers, pair requests, quiz turns) and two schedules: calendar reminders on server calendars (every minute, deduplicated by tag `cal-rem-<fireKey>` with the in-app reminder) and Our Pet needing care (at most every 8 hours). Deep links: `/?open=im&with=NAME`, `?open=call&with=`, `?open=mail`, `?open=calendar&cal=&event=`, `?open=program&name=`, `?open=invites`, `?open=notifications` (they skip the boot screen and Welcome).

In Safari the settings show an illustrated Add to Home Screen guide; once opened from the Home Screen they show "Turn on notifications". The manifest (`client/public/manifest.webmanifest`, standalone, icons 192/512/maskable, `apple-touch-icon` 180 in `index.html`) is what iOS needs.
  - **User profiles** (`utils/users.js`): each person on a device has their own desktop, drive, settings and scores. THE STORAGE SEAM: `userKey("98ish.x")` maps a key to the logged-on person's (`98ish.u.<id>.x`; the default user keeps the plain keys, so a device's existing data is the first user's). `utils/userStorage.js` (imported first in `main.jsx`) applies it to localStorage getItem/setItem/removeItem, so plain localStorage code needs nothing. Any other store (IndexedDB) must call `userKey()`/`keyPrefix()` itself and register `onUserRemoved(fn)`. Device keys (`GLOBAL_KEYS`: `98ish.users`, `98ish.currentUser`, `98ish.lock`...) stay shared. Switching users reloads the page (`switchUser`).
  - **Lock screen** (`utils/lock.js`, `utils/lockCrypto.js` PBKDF2-SHA256 600k with a random salt, `utils/lockTimers.js`, `OS-specific/lock/`): PIN or password per user (hash in the user's profile), Start > Lock Computer, Win+L / Ctrl+Alt+L, idle wait (`lockAfter`), screen saver (`lockOnSaver`), reopen after the wait; state in `98ish.lock` survives reloads. Wrong tries wait 5s, 15s, 45s... While locked the desktop stays mounted but hidden (`html.os-locked`), keys are stopped in lock.js, arrivals call `notifyLocked()` ("New message" only), and CallManager hands the ringing call to the lock screen (Decline at once, Answer after the PIN). "Forgot PIN?" signs in to the linked 98 Messenger screen name (`aim:verify`, no session) or, with none linked, removes the lock after a warning. Settings: Start > Settings > Passwords and Users (`applets/passwords/`). Log On (`lock/LogOn.jsx`) picks or creates users.

    - Out: `utils/share.js` `shareOut(payload, "phone" | "apps")` (Web Share API; call it straight from the tap, no awaits first, or iOS refuses) with fallbacks: download the file, or copy the text (a 98 message via `ShareCenter`). Payload rules are pure in `utils/shareRules.js` (tested: `node --test client/src/utils/shareRules.test.js`). "Send To > My Phone / Other Apps..." is in My Computer, desktop files, Notepad, WordPad, Paint, Sound Recorder, Photos' Share menu, Camera (File menu + a Share button after a shot), Calendar event "Share..." (.ics), Speed Typist "Share Result...", Word Duel "Share..." (plus "Copy"). `MenuBar` now supports submenus (`items` on an item).
    - In: `manifest.webmanifest` `share_target` (POST multipart to `/share-target`) -> `public/sw.js` keeps it in the `share-inbox` cache (not `98ish-*`, so updates don't clear it) and redirects to `/?share-target=<id>`; `OS-specific/ShareCenter.jsx` (lazy, on the desktop) shows **Received Items** and saves via `utils/receive.js` (pictures -> JPEG in My Pictures, other files -> My Documents, links -> desktop Internet Shortcut and/or IE, text -> a Notepad document). GET `/share-target?title&text&url` works too (vercel.json rewrite for no-SW visits). **Only Android Chrome (installed app) and ChromeOS can be share targets; iOS Safari can't** (WebKit bug 194593, open as of 2026). iPhone path: "Upload from Phone..." (desktop right-click, My Computer File menu + toolbar Upload) and Paste.
    - Clipboard: `utils/systemClipboard.js`. Copying a file in My Computer/desktop (`fsActions.setClipboard`) mirrors its words / URL / picture to the system clipboard; Paste with nothing copied in 98ish (and "Paste from Device Clipboard") reads the system clipboard (pictures, links, text); Ctrl+V / the phone's Paste use the paste event. Notepad/WordPad Cut/Copy fall back to the Clipboard API.

    - **How pages get in:** most sites refuse frames, so the page comes through the relay: `/api/web/r/<sid>/<tok>/<d|f>/https/host/path` (`rewrite.js` is a small tokenizer that rewrites links/forms/frames/src/srcset/CSS url()/meta refresh/base; `inject.js` is put first in every page and reports url/title/favicon/password boxes to Compass by postMessage, routes link clicks, GET forms, `window.open`, `fetch`/XHR/beacons/EventSource, `history.pushState` and Navigation API navigations through the relay, stands in for `document.cookie` and localStorage, and does find/zoom/stop). Mode `d` (default): pictures and scripts load straight from https sites (saves server data; sites see the person's IP); stylesheets and fonts are addressed through the relay (fonts need CORS), which answers with a 302 to the site itself whenever the browser can load it directly (`goDirect` in index.js: a font when the site sends `Access-Control-Allow-Origin: *`; a stylesheet without `@font-face` when the request is no-cors or the site allows any origin; a stylesheet WITH fonts becomes a tiny sheet `@import url(<site's sheet>)` + only its @font-face rules with relay URLs; data: fonts need nothing; sheets with `@import` are still rewritten in full). Mode `f` (View > Relay Pictures Too): everything relayed. Data Saver puts frameable sites (checked by `/api/web/check`, headers only) straight into the frame. Sites in `NO_RELAY_SITES` (urls.js `skipRelay`: Google sign-in, YouTube and video sites, banks, PayPal, social apps) are never relayed.
    - **Sites that aren't relayed show inside Compass anyway (2026-10-04; there is no "open in your real browser" page any more):** off the allowlist, relay off (`WEB_RELAY=0`), server unreachable, closed for the month, day's budget used, `NO_RELAY_SITES`, and relay stubs `notallowed|monthly|budget|unavailable|off|error|toobig|media` all go to `withoutRelay()` in Compass.jsx: (1) `GET /api/web/frame?url=` (no session, ANY public host, headers only: the socket is destroyed after the headers, same SSRF guard incl. every redirect hop, 60/min per address + `WEB_FRAME_CHECKS_PER_MIN` 1200/min total, cached 10 min, ~600 B + header bytes counted in `day|frames`, `day|relay`, `month|compass`; `WEB_FRAME_CHECK=0` turns it off; `frameVerdict()` = browser rules: CSP frame-ancestors wins (each policy must match the asking 98ish Origin), else XFO DENY/SAMEORIGIN; 401/403/429/5xx count as not frameable) -> a frameable https page (or any page when 98ish is http) loads straight from the site in `DIRECT_SANDBOX` (never 98ish's own origin: `sameOrigin()`); (2) else the Internet Archive's newest good copy: `/api/wayback?action=sparkline` (now also returns `lastTs` and per-month `status`; `newestCapture()` picks the newest month with status "2") -> `https://web.archive.org/web/<ts>if_/<url>` in `ARCHIVE_SANDBOX` (scripts + same-origin as web.archive.org, forms, popups; no modals/top navigation/escape) with a slim `.cmpArchiveBar` "Saved copy from the Internet Archive, <date>. This site can't be shown live in Compass." + a small "Open in Safari" link; the Archive's `playbackReady/domContentLoaded` messages (origin `https://web.archive.org`, from the tab's frame only) set the address bar to the original URL (`parseArchiveUrl`), the title, the copy's date, and push a history entry for links followed inside the copy; (3) no copy at all: stub kind `nosnapshot` "This site can't be shown in Compass" with Search Wikipedia for "<name>" / Try Again and a small Open in Safari link. Direct and archived pages load over the visitor's own connection (the site / the Archive see their IP). Compass accepts `__compass` messages only from relayed (opaque-origin) frames: direct frames are ignored entirely. Find, Save Page to Drive need the relay. The first bookmarks (DuckDuckGo, HN, BBC, wttr.in...) are swapped once (`prefs.bookmarksVersion`, `migrateBookmarks`) for Wikipedia, Featured Article, Wiktionary, Wikivoyage, OpenStreetMap, Space Jam (1996, archive), Cameron's World (framable), The First Website, Zombo.com. The `alwaysReal` preference and its menu items are gone.
    - **"True internet" (the code default since 2026-10-04, decided with the owner, who knows Render's AUP clause on bypassing network restrictions and accepts it):** `WEB_RELAY` unset = `on`: signed-on 98 Messenger accounts browse ANY public site live through the relay and search with DuckDuckGo's HTML page (`html.duckduckgo.com/html/?q=`, light and relay-friendly; checked live); guests keep the allowlist through the relay and see every other site straight from the site or as a saved copy with a slim bar **"Sign on to browse this site live. Sign On / Get a Screen Name"** (no interstitial; `why: "signon"`; when the Archive has no copy either, a `signon` stub). Signing on (from the bar, Compass's SignOnDialog, or 98 Messenger) reloads every waiting tab (`t.why === "signon"`) live. `WEB_RELAY=allowlist` (everyone only the allowlist; also any unknown value) and `0`/`off` still work as switches.
    - **Routing table** (Compass.jsx `resolveView`): month closed (`session.closed`) -> everyone without the relay, bar "Live browsing resumes on <the 1st>"; guest + allowlisted -> relay; guest + other site -> direct/saved copy + sign-on bar; signed on + any site -> relay; today's allowance used (`used >= limit` or `session.dayFull`, which also covers the whole relay's / all guests' day) -> direct/saved copy + "Live browsing resumes tomorrow"; a relay stub `budget`/`monthly`/`signon` mid-browsing does the same (and `refreshUsage()` so the next pages skip the relay); the site answers the server with a robot check -> relay stub `siteblocked` -> direct/saved copy with "This site blocks the 98ish server"; blocked site -> a stub "Compass doesn't open this site" (no direct frame, no saved copy: `/api/web/frame` answers `blocked`). Searches use Wikipedia for guests and whenever the session is closed/dayFull.
    - **Safeguards (2026-10-04):**
      - Bandwidth, measured with real Chrome through the local relay against the real internet (scratchpad `web5/measure.mjs`, first view of a page / a second page on the same site; relayed bytes incl. headers as counted by the relay): Hacker News 11/12 KB, DuckDuckGo results 10/10, Simon Willison's blog 29/27, BBC News 70/65, old.reddit 69/69, Wikipedia 88/75, GitHub repo 94/59, Guardian 186/129, NPR 247/205, IKEA category 281/246, MDN 290/282 (its fonts refuse other origins, so they're relayed), Allrecipes 326/325. **Average about 130 KB relayed per page view** (the sites themselves sent 2.6 MB per page straight to the browser). Before the stylesheet/font redirects it was 280 KB (NPR 680, GitHub 438); browsers don't reuse cached relayed stylesheets across pages because an opaque-origin frame gets no shared HTTP cache, so every page re-fetches them. So `WEB_MONTHLY_MB` 1000 is roughly **7,500 live page views a month** (about 250 a day for everyone together), and the per-account day (`WEB_DAILY_MB`, now **25**) about 190 pages. The relay's own XHR/fetch (`/x/`) stays relayed (CORS; also keeps "Relay Pictures Too" private).
      - Caps never shut Compass off: the session reports `dayFull` and `resumes`; budget/monthly stubs fall back (above). Messenger and the rest of 98ish are never cut.
      - Blocklist (`server/web/blocklist.js`, `blockedSite(host, ownerList)`): `WEB_BLOCK_HOSTS` (owner, with subdomains) plus a compact built-in list by category: malware/phishing TEST and sample sites (testsafebrowsing.appspot.com, eicar.org, wicar.org, malware-traffic-analysis.net...), adult (the biggest ~35 hosts, `.xxx/.porn/.adult/.sex/.sexy` TLDs, host-name words porn/xxx/hentai/nsfw/xvideo/xhamster/onlyfans/chaturbate...; NOT "sex" alone, so Sussex/Essex pass), piracy (Pirate Bay, 1337x, YTS, libgen, Z-Library, Sci-Hub, Anna's Archive, streaming mirrors...), other proxies/Tor gateways. A full public-domain adult list (Block List Project, Unlicense) is hundreds of thousands of hosts, too big; limits: innocent-named sites get through, a harmless name containing a keyword is refused. Checked on every hop via the guard's `denyHost` (relay, redirects before the 302 goes out, `/check`, `/frame`).
      - Report This Page (Tools menu; phone menu sheet): `POST /api/web/report { sid, url, note }` -> MongoDB `webreports` `{ account, guest, host, url, note (1000 chars), time, expiresAt }`, TTL 90 days, 10 per hour per session key, nobody notified. The owner reads them in Atlas/mongosh: `db.webreports.find({}, { _id: 0, host: 1, url: 1, note: 1, time: 1 }).sort({ time: -1 })` or counts per host `db.webreports.aggregate([{ $group: { _id: "$host", n: { $sum: 1 } } }, { $sort: { n: -1 } }])` (chosen over an owner-token endpoint: no new auth surface).

  - `saveNow()` and `writeAndSave()` are async (resolve false on a full disk; callers await them). Saves run 40 ms after a change: a browser drops IndexedDB writes started while a page closes, so the window stays tiny.
  - First start after the update moves the old localStorage drive (`98ish.fs.v1`): one transaction, read back and compared file by file, then marked (`98ish.fs.migrated` + IndexedDB `meta.migration`). The old copy stays 3 days. A failed move changes nothing and is retried next start (meanwhile the old drive works). Without IndexedDB (some private windows) the old 5 MB localStorage drive is used, and `StorageNotice` says so; if IndexedDB was used before but won't open, the drive opens read-only-ish ("changes won't be saved").
