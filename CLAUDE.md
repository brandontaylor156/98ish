# 98ish: notes for the next session

A Windows 98-style web desktop at https://98ish.vercel.app. The owner uses it mostly on an iPhone and shares it with his girlfriend and friends.

## Layout
- **Client:** React 19 + Vite in `client/`, deployed by Vercel on every push to `main`.
  - Apps live in `client/src/components/applets/<app>/` and load lazily from `OS-specific/Desktop.jsx` (`lazyApp`).
  - Each app is registered in several places: `utils/programs.js` (fields `group` and optional `also: [...]` for Start menu folders, plus `online: "<id>"` for room games), `applets/dos/commands.js`, `applets/taskManager/processes.js`, `OS-specific/Helper.jsx` (Floppy tips), `utils/fs.js`, `utils/imageMapper.js`, an icon in `client/public/assets/program_icons/`, and a 98ish Help topic claiming it (`applets/help/topics/`; the help unit test fails without one).
- **Server:** `server.js` + `server/*` (Express, Socket.io, MongoDB), deployed by Render (service `srv-davi6cm7bikc73e5k5ig`) on every push.
  - Online games use the room system `server/arcade/rooms.js`, which has a guide at the top. Rules modules are in `server/arcade/games/`.
  - The client side of the room system is `client/src/components/shared/online/`.
- **Shared systems:**
  - **Audio** (`client/src/utils/audio.js`): one AudioContext and `createBus`, following the taskbar volume and mute.
  - **Draggable dialogs** (`shared/Dialog.jsx` + `hooks/useFloating.js`). During a drag the popup follows the pointer through left/top written once per frame from a containing-block origin measured at the press (which also re-reads where the box is drawn, so nothing that moved it can cause a jump); letting go measures and moves nothing (the older translate-then-commit release snapped the box elsewhere on a real iPhone, not reproducible in Chrome or Playwright WebKit). Ends on pointerup/pointercancel/lostpointercapture (never stuck). `?dragdebug=1` (remembered per browser; `=0` off) shows an on-screen log per release: drawn before -> after -> 300 ms later, plus refits. Phones: the title bar takes the gesture (`touch-action: none`, non-passive touchstart/touchmove preventDefault, no callout/selection, no long-press menu), a second finger can't take over, a finger's press never focuses a text field (it raised the 98ish keyboard mid-drag), and the whole popup stays inside the safe areas, above the taskbar and above the 98ish keyboard (it refits when `html.kb-open`/`--kb-h` change; the keyboard no longer `translate`-lifts `[data-floating=on]` boxes, which used to jump back when it hid). Mouse dragging is unchanged (60 px of title bar kept off-edge). Browser tests: `drag-phone.mjs` (CDP touch), `drag-webkit.mjs` (Playwright WebKit iPhone 14, iOS-ordered synthetic touch pointer events: `npx playwright-core install webkit`), `drag-desktop.mjs`; each checks no snap at release, a frame later and 300 ms later.
  - **Right-click menus** (`shared/ContextMenu.jsx`, rendered into `.os-root`) and the global right-click menu (`OS-specific/GlobalMenu.jsx`).
  - **No phone "hold" menus** (`main.css` "No phone hold menus" block + `utils/touchGuard.js`, installed in `main.jsx`; test `node --test client/src/utils/touchGuard.test.js`). THE RULE: everything is `user-select: none` + `-webkit-touch-callout: none` (set on `body`; Safari needs the `-webkit-` prefixes, always write both), so a hold never shows the loupe, Copy/Look Up or Save Image. Allowed automatically: text inputs, textareas, contenteditable. Opt a reading area in with `data-selectable` (or class `selectable`); `data-selectable="mouse"` = mouse only (Messenger's transcript, where a held message opens reactions; their box has Copy); `data-selectable="false"` off again inside one; `.dialogBody p` (error/notice words) is allowed. Buttons, labels, title bars and `[role=button|menuitem|tab]` are never selectable, even inside an area. Pictures/canvases/video never offer Save Image or drag out (Photos has Save/Share menus). Opted in now: Mail text, Help topics, Address Book details, Calendar event notes/location, Notepad/WordPad, game chat and logs, Calculator display, Task Manager messages. Since iOS 18 a tap followed by a hold shows the loupe even over `user-select: none` (WebKit bug 296492), so TOUCH SURFACES cancel `touchstart`: mark an element `data-touch-surface` (or add to `SURFACE_SELECTOR`: TouchControls zones/buttons and Pickleball's court are listed there). Only on things driven by pointer events (a cancelled touchstart means no `click`) that don't scroll by dragging (Minesweeper's board scrolls, so it relies on CSS). Marked: Shred, Hover, Downhill, SPECTRA, Tetherball, Our Pet's catch game, Echo Pads, Zap It!, Boom Frenzy's field, Tetris while swiping. A finger's `contextmenu` (Android) outside fields is cancelled even if a handler only stops it. iPhones send no `contextmenu` on a hold, so app menus need `useLongPress` (Photos tiles now have it). Audit scripts `lp-audit.mjs` (WebKit, every program: styles at title bar/buttons/pictures/fields/text) and `lp-behave.mjs` (Chrome: long-press menus, Minesweeper flag, reactions Copy, touch surfaces).
  - **Touch controls** (`shared/controls/`). The editor panel takes a game's own options through the `settings` prop (exported `Check`/`Slider` match its look).
  - **Tetris swipe controls** (like the Tetris phone app): rules in `applets/tetris/utils/gestures.js` (pure tracker, thresholds in `GESTURE`; tests `node --test client/src/components/applets/tetris/utils/gestures.test.js`), wired by `hooks/useSwipeControls.js` (pointer events with coalesced samples on the whole Tetris window, skipping buttons; `touch-action: none` via `data-scheme`, non-passive touchmove, contextmenu cancelled) into `useTetris().step` (one column/row, no DAS; returns false at a wall so the drag re-anchors). Drag sideways = the piece follows the finger in cells from the touch start (x sensitivity), drag down slowly = soft drop per cell, flick down (>= 0.7 px/ms over the last 64 ms, 2x its sideways speed, >= 20 px, only while the drag is locked downward) = hard drop, swipe up (>= 1.5 cells) = hold, tap (< 9 px, < 500 ms) = right half CW, left half CCW like the app (option off: every tap CW). The first decisive move locks an axis; switching needs 1.2 cells on the other axis; after a hard drop/hold, or when the piece locks, the rest of the touch is ignored; a second finger is ignored. Settings (`utils/touchPrefs.js`, localStorage `98ish.tetris.touch`, per user): scheme `app` ("Like the Tetris app", default on touch: swipes + a Hold button + Pause) / `gestures+buttons` / `gestures` / `buttons` (the classic d-pad), sensitivity 0.5-2, tapSides (default on); `v: 2` prefs (older saved prefs with the old defaults move to app + tapSides); chosen in the controls editor (`components/TouchSettings.jsx`). Each scheme saves its own button layout (`controlsGameFor`: `tetris`, `tetris-gestures`, `tetris-swipe`, `tetris-app`). **App layout** (portrait + `app` scheme, `data-layout="app"` in TetrisWindow, CSS in Tetris.css): top strip with Pause (left) and the gear (right), the mode's first stat big above the board, Hold + the other stats in a 48 px left column (`APP_SIDE`), Next (3 pieces) on the right, board as wide as the columns allow (68% of a 390 px screen) and sitting below the middle (free height 1 : 0.5 above/below; the window is the size container), Hold/Item buttons in the bottom corners. Research and before/after numbers: `docs/tetris-mobile.md`; landscape keeps the side layout. A one-time how-to card (`98ish.tetris.swipeHint`). No vibration on iOS (8 ms on Android for hard drop/hold when "Vibrate on press" is on). Browser tests `tet-gest-solo.mjs`, `tet-gest-online.mjs` (scratchpad); older touch suites that expect the d-pad must set `98ish.tetris.touch` to `{"scheme":"buttons"}`. Browser tests `tet2/solo.mjs <390x844|430x932>`, `tet2/online.mjs` (Battle 2P + Arena with bots), `tet2/desk.mjs`, `tet2/measure.mjs` (layout %) in the scratchpad. Under a loaded machine CDP moves arrive ~50 ms apart, so test flicks send few, big, undelayed moves.
  - **98ish phone keyboard** (`shared/keyboard/`; design in `docs/keyboard.md`). Enter's label (`fields.js` `enterLabel`): the field's `enterKeyHint`, else search/url/multi-line, a dialog's default button (`data-kb-enter` from `Dialog.jsx`), Go in other forms, else Enter; never "Done" by itself. `enterKeyHint="next"` moves on without submitting. While it's up on a phone, window status bars hide (`data-kb-status="keep"` keeps one; YouTube's "Done" status read as part of the keyboard) and chat transcripts stay at the newest line. `data-kb-auto` + `requestKeyboard(el)` (`native.js`) bring it up with no tap (Speed Typist's race box at GO and when the race comes back into view). Browser scripts `kb2-*.mjs` (labels, chat/IM/Mail/dialog/game-chat layout, Speed Typist), sound on a phone `snd2-phone.mjs`.
  - **98-style drop-downs and date/time pickers** (`shared/select/`, `SelectHost` mounted once in App.jsx): takes over every `<select>` and `input[type=date|time|datetime-local|month]` with no change at the call sites. Touch: the tap's `touchend` is cancelled (no focus, so no iOS picker); a list drops down under the field like the mouse one (40px rows on phones; the owner wanted a real drop-down, 2026-10-04) and only date/time pickers open as a 98 bottom sheet (older `sel-*` scripts that wait for `.selSheet .selList` need `.selDrop .selList`); mouse: the `mousedown` is cancelled and a list/calendar drops down (date fields keep typing; only their button opens the calendar); keys: Alt+Down/F4/Space. Choices go through the native value setter plus `input`/`change` events, so React state updates. Opt out with `data-native-select`; `multiple`/`size>1` lists stay native. Tests: `select.test.js`, browser scripts `sel-*.mjs`.
  - **98 Messenger calls** (1:1 voice/video, WebRTC): signaling in `server/aim/calls.js` (relays only between the two people in a call; busy, ring timeout, block, drop handling), ICE servers in `server/aim/ice.js`, client in `applets/aim/call/` (`engine.js` holds the call and the peer connection outside React; `CallManager.jsx` rings, opens windows, shows toasts; `CallWindow.jsx`, `RingWindow.jsx`). Calls start from the IM window header, a buddy's right-click menu, and Us ("Video call [partner]").
  - **Notification Center** (`utils/notifications.js`, taskbar bell `OS-specific/NotifyTray.jsx` + `Notify.css`, settings `NotifySettings.jsx` (lazy), `NotifyBridge.jsx` inside the Messenger provider): every toast (IMs, missed calls, Mail, Calendar, couples, game invitations, achievements, drive sync) also calls `notify({ app, title, text, key, target })`. Items merge by `key` (an IM and its push are one item), are kept per account in localStorage (`98ish.notifications`), and `target` is plain data (`{ kind: "im", with }`, `mail`, `calendar`, `program`, `invites`, `notifications`) that NotifyBridge opens. "Mark all read" / "Clear all" sync a `seenAt` per account to the server. Start > Settings > Notifications... opens the settings.
  - **Web Push** (`server/push/`, client `utils/push.js`, handlers at the end of `client/public/sw.js`): subscriptions per account and device, categories (im, calls, calendar, couples, mail, games, notes), quiet hours (calls can ring through), 404/410 subscriptions deleted. A push goes out only when the person is away from 98ish: signed off, connection gone, or the tab hidden (the client sends `aim:visibility`). Triggers: IMs (IMs to someone signed off who has push on are kept and delivered at sign on; MongoDB collections `pushsubs`, `pushprefs`, `pushinboxes`), calls (a signed-off buddy with push still rings by notification; the ring reaches them if they open 98ish while it rings; missed calls), Mail, game invitations, couple notices (letters, flowers, pair requests, quiz turns) and two schedules: calendar reminders on server calendars (every minute, deduplicated by tag `cal-rem-<fireKey>` with the in-app reminder) and Our Pet needing care (at most every 8 hours). Deep links: `/?open=im&with=NAME`, `?open=call&with=`, `?open=mail`, `?open=calendar&cal=&event=`, `?open=program&name=`, `?open=invites`, `?open=notifications` (they skip the boot screen and Welcome).
  - **iPhone:** Web Push works only for 98ish added to the Home Screen (iOS 16.4+), and the permission prompt has to come from a tap. In Safari the settings show an illustrated Add to Home Screen guide; once opened from the Home Screen they show "Turn on notifications". The manifest (`client/public/manifest.webmanifest`, standalone, icons 192/512/maskable, `apple-touch-icon` 180 in `index.html`) is what iOS needs.
  - **User profiles** (`utils/users.js`): each person on a device has their own desktop, drive, settings and scores. THE STORAGE SEAM: `userKey("98ish.x")` maps a key to the logged-on person's (`98ish.u.<id>.x`; the default user keeps the plain keys, so a device's existing data is the first user's). `utils/userStorage.js` (imported first in `main.jsx`) applies it to localStorage getItem/setItem/removeItem, so plain localStorage code needs nothing. Any other store (IndexedDB) must call `userKey()`/`keyPrefix()` itself and register `onUserRemoved(fn)`. Device keys (`GLOBAL_KEYS`: `98ish.users`, `98ish.currentUser`, `98ish.lock`...) stay shared. Switching users reloads the page (`switchUser`).
  - **Lock screen** (`utils/lock.js`, `utils/lockCrypto.js` PBKDF2-SHA256 600k with a random salt, `utils/lockTimers.js`, `OS-specific/lock/`): PIN or password per user (hash in the user's profile), Start > Lock Computer, Win+L / Ctrl+Alt+L, idle wait (`lockAfter`), screen saver (`lockOnSaver`), reopen after the wait; state in `98ish.lock` survives reloads. Wrong tries wait 5s, 15s, 45s... While locked the desktop stays mounted but hidden (`html.os-locked`), keys are stopped in lock.js, arrivals call `notifyLocked()` ("New message" only), and CallManager hands the ringing call to the lock screen (Decline at once, Answer after the PIN). "Forgot PIN?" signs in to the linked 98 Messenger screen name (`aim:verify`, no session) or, with none linked, removes the lock after a warning. Settings: Start > Settings > Passwords and Users (`applets/passwords/`). Log On (`lock/LogOn.jsx`) picks or creates users.

Payload rules are pure in `utils/shareRules.js` (tested: `node --test client/src/utils/shareRules.test.js`). "Send To > My Phone / Other Apps..." is in My Computer, desktop files, Notepad, WordPad, Paint, Sound Recorder, Photos' Share menu, Camera (File menu + a Share button after a shot), Calendar event "Share..." (.ics), Speed Typist "Share Result...", Word Duel "Share..." (plus "Copy"). `MenuBar` now supports submenus (`items` on an item).
    - In: `manifest.webmanifest` `share_target` (POST multipart to `/share-target`) -> `public/sw.js` keeps it in the `share-inbox` cache (not `98ish-*`, so updates don't clear it) and redirects to `/?share-target=<id>`; `OS-specific/ShareCenter.jsx` (lazy, on the desktop) shows **Received Items** and saves via `utils/receive.js` (pictures -> JPEG in My Pictures, other files -> My Documents, links -> desktop Internet Shortcut and/or IE, text -> a Notepad document). GET `/share-target?title&text&url` works too (vercel.json rewrite for no-SW visits). **Only Android Chrome (installed app) and ChromeOS can be share targets; iOS Safari can't** (WebKit bug 194593, open as of 2026). iPhone path: "Upload from Phone..." (desktop right-click, My Computer File menu + toolbar Upload) and Paste.
    - Clipboard: `utils/systemClipboard.js`. Copying a file in My Computer/desktop (`fsActions.setClipboard`) mirrors its words / URL / picture to the system clipboard; Paste with nothing copied in 98ish (and "Paste from Device Clipboard") reads the system clipboard (pictures, links, text); Ctrl+V / the phone's Paste use the paste event. SSRF guard (`guard.js`): http(s) only, ports 80/443/8080/8443, no credentials in URLs, no local names, no own host names, every DNS answer must be public unicast (IPv4 + IPv6 incl. mapped/NAT64/6to4/Teredo/ULA/link-local/metadata), and the socket connects to the checked address (no second lookup, so no DNS rebinding); redirects go back to the browser as relay URLs so every hop is checked again. **Isolation (audited 2026-10-04):** relayed documents come from nine8ish.onrender.com, which is also the API origin, so they must never run as it: pages get `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-modals allow-pointer-lock` (no allow-same-origin, no top navigation, no allow-popups-to-escape-sandbox, which used to be there and would have let an unsandboxed popup navigate the 98ish tab through `opener.top`), and Compass's `<iframe sandbox>` matches (`RELAY_SANDBOX`/`DIRECT_SANDBOX`, neither escapes). Every other `/api/web` answer (JSON, scripts, pictures, errors, redirects, preflights) gets a script-less `sandbox` CSP + nosniff from a router middleware. CORS on the relay is `*` and never `Access-Control-Allow-Credentials` (it used to echo the origin with credentials); `inject.js` makes pages' fetch/XHR/EventSource leave credentials out and gives them in-memory localStorage/sessionStorage (methods on the prototype) and document.cookie (the server jar). ## Storage and sync
- **Vercel Blob checked against the real store (2026-10-04):** from a page at https://98ish.vercel.app in real Chrome, a presigned PUT (headers only `x-api-version`, `x-vercel-blob-access`, `x-content-type`: Vercel's CORS allow-list doesn't include `x-add-random-suffix`/`x-allow-overwrite`, and the signed URL already pins them) and a presigned GET work (`Access-Control-Allow-Origin: *`); unsigned GETs, oversize PUTs and overwrites are refused; `head()` reports the size. - **The drive** (`utils/fs.js`, `utils/driveStore.js`): the synchronous tree API is unchanged, but the drive is kept in IndexedDB (database `98ish-drive`: `meta` holds the folder index with small files inline, `contents` holds big texts keyed by a content hash, so copies share storage and unreferenced contents are deleted in the same transaction). `main.jsx` renders nothing until `fsReady` (a "Loading your files..." screen after 300 ms). `navigator.storage.persist()` is requested at start.

## Game performance (wave 1, 2026-10-04)
- **The clock rule:** a game loop measures real time with `utils/frameClock.js` (`createFrameClock().tick(rafTime)`). Keep `last` across frames; `reset()` only when the loop starts again after a stop (start/resume, resize, context restore, the tab coming back), never in the per-frame reschedule. (Pickleball and SPECTRA reset it every frame, so every frame counted 16 ms: half speed at 30 fps, double at 120 Hz.) Long frames clamp at 100 ms. Pickleball's physics already runs fixed 1/240 s steps (`match.advance`); SPECTRA's `logic.step` takes at most 50 ms, so the engine splits a frame into `substeps(dt, 1/30)` and handles events after each. Test: `node --test client/src/utils/frameClock.test.js` (clock + resolution); browser `hz.mjs` (rAF shim at 120/60/42/30 Hz) in the wave1 scratchpad.
- **Dynamic resolution:** `utils/dynamicResolution.js` (`createResolution({ max, min: 1 })`, fed each frame's interval and main-thread work): a 0.25 step down when a 2 s window averages 15% over the target (16.7 ms, or 33.3 ms on a device capped at 30 fps: steady ~33 ms frames with little work), back up after 3 good windows (6 when retrying the ratio that last failed); floor 1.0. Used by Pickleball (max = the quality's ratio: Low 1, Medium 1.5, High 2) and SPECTRA.
- **Anti-aliasing and DPR caps:** Pickleball, SPECTRA and Shred create their renderers with `antialias: true` everywhere; SPECTRA and Shred draw a 2x/3x screen at 1.5 (with AA that's sharper than 2 without, and cheaper). Canvas 2D games cap devicePixelRatio at 2 (Downhill/Ski, Pinball; Hover, Town, Dollhouse already did): a 2D canvas costs by the pixel.
- **Shaders compiled ahead:** Pickleball calls `warm()` (`renderer.compileAsync(scene, camera)`, KHR_parallel_shader_compile) after any change that brings new programs (venue + its lights, figures, athletes loading, quality, the Locker Room figure). While it compiles the last picture stays up (not during a match: that frame waits as before); the first warm-up is behind "Loading the court..." (`engine.ready`). `renderer.debug.checkShaderErrors` is dev-only (the info-log reads made every compile block). A venue switch went from a 0.9-1.3 s long task to 0.3-0.4 s (what's left is building the venue on the CPU). Athletes are still built in one go at Play (~60-100 ms; spreading them over frames would need placeholder figures or touching athlete.js).
- **Look:** the sky shader ends with `#include <colorspace_fragment>` (any custom ShaderMaterial must, or its colors come out darker than designed). Shadows (Medium/High): 2048 map, PCF radius 3, shadow camera fitted to the court + run-off as the light sees it (`fitShadow` in venue.js); every quality adds a small dark contact blob under each player's feet (Low has no shadow map). The big screen shrinks long names to fit and goes blank on an upright phone, where the HUD score panel covers it (`venue.setScreenCompact`).
- **Per-frame waste:** gamepads are polled only after `gamepadconnected` (or a pad already known at start); the touch stick's knob moves by a ref, not React state; meter CSS variables and data attributes are written only on change; the ball trail writes its typed arrays directly; replay copies only while recording. Desktop: `selectActive` skips the dispatch when the tapped window is already the one active window, and the `select_active` reducer returns the same state when nothing changes (pointerdown handling 26-42 ms -> 1-5 ms in a production build).
- **WebGL context loss:** `utils/webglLoss.js` `releaseGpu(scene)` in the `webglcontextlost` handler (Pickleball, SPECTRA) disposes GPU resources while the context is gone, so nothing is deleted against the restored context ("object does not belong to this context").
