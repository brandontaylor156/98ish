# Compass, the real web browser, and its relay
Everything about Compass: routing, the relay, safeguards, budgets, Render numbers and terms, security review and tests. Moved from CLAUDE.md on 2026-10-05.

  - **Compass, the real web browser** (`applets/compass/`, server `server/web/`): tabs (drag to reorder), omnibox (URL or search; DuckDuckGo's HTML page by default, Bing/Mojeek/Wikipedia in Tools > Compass Options), back/forward/reload/stop/home, bookmarks bar + Bookmarks page (imports IE Favorites and `C:\Bookmarks`), searchable History, Downloads (Save to 98ish Drive into `C:\Downloads` through `utils/receive.js`, or to the device via the real browser), find in page, zoom (remembered per site), File > Open in Safari/Chrome/... (`openInLabel`, a small secondary way out; no toolbar button), View > Show Saved Copy, Open in Time Machine (IE), phone layout (bottom bar, tab sheet, menu sheet). Bookmarks/history/tabs are per user (`98ish.compass.*`). It's the default for web links (`webWindow(url)` in programs.js: 98ish.com pages stay in IE; `openItem`, Run/`start`, ShareCenter use it). DOS: `compass`, `browser`, `web`, `www`.
    - **How pages get in:** most sites refuse frames, so the page comes through the relay: `/api/web/r/<sid>/<tok>/<d|f>/https/host/path` (`rewrite.js` is a small tokenizer that rewrites links/forms/frames/src/srcset/CSS url()/meta refresh/base; `inject.js` is put first in every page and reports url/title/favicon/password boxes to Compass by postMessage, routes link clicks, GET forms, `window.open`, `fetch`/XHR/beacons/EventSource, `history.pushState` and Navigation API navigations through the relay, stands in for `document.cookie` and localStorage, and does find/zoom/stop). Mode `d` (default): pictures and scripts load straight from https sites (saves server data; sites see the person's IP); stylesheets and fonts are addressed through the relay (fonts need CORS), which answers with a 302 to the site itself whenever the browser can load it directly (`goDirect` in index.js: a font when the site sends `Access-Control-Allow-Origin: *`; a stylesheet without `@font-face` when the request is no-cors or the site allows any origin; a stylesheet WITH fonts becomes a tiny sheet `@import url(<site's sheet>)` + only its @font-face rules with relay URLs; data: fonts need nothing; sheets with `@import` are still rewritten in full). Mode `f` (View > Relay Pictures Too): everything relayed. Data Saver puts frameable sites (checked by `/api/web/check`, headers only) straight into the frame. Sites in `NO_RELAY_SITES` (urls.js `skipRelay`: Google sign-in, YouTube and video sites, banks, PayPal, social apps) are never relayed.
    - **Sites that aren't relayed show inside Compass anyway (2026-10-04; there is no "open in your real browser" page any more):** off the allowlist, relay off (`WEB_RELAY=0`), server unreachable, closed for the month, day's budget used, `NO_RELAY_SITES`, and relay stubs `notallowed|monthly|budget|unavailable|off|error|toobig|media` all go to `withoutRelay()` in Compass.jsx: (1) `GET /api/web/frame?url=` (no session, ANY public host, headers only: the socket is destroyed after the headers, same SSRF guard incl. every redirect hop, 60/min per address + `WEB_FRAME_CHECKS_PER_MIN` 1200/min total, cached 10 min, ~600 B + header bytes counted in `day|frames`, `day|relay`, `month|compass`; `WEB_FRAME_CHECK=0` turns it off; `frameVerdict()` = browser rules: CSP frame-ancestors wins (each policy must match the asking 98ish Origin), else XFO DENY/SAMEORIGIN; 401/403/429/5xx count as not frameable) -> a frameable https page (or any page when 98ish is http) loads straight from the site in `DIRECT_SANDBOX` (never 98ish's own origin: `sameOrigin()`); (2) else the Internet Archive's newest good copy: `/api/wayback?action=sparkline` (now also returns `lastTs` and per-month `status`; `newestCapture()` picks the newest month with status "2") -> `https://web.archive.org/web/<ts>if_/<url>` in `ARCHIVE_SANDBOX` (scripts + same-origin as web.archive.org, forms, popups; no modals/top navigation/escape) with a slim `.cmpArchiveBar` "Saved copy from the Internet Archive, <date>. This site can't be shown live in Compass." + a small "Open in Safari" link; the Archive's `playbackReady/domContentLoaded` messages (origin `https://web.archive.org`, from the tab's frame only) set the address bar to the original URL (`parseArchiveUrl`), the title, the copy's date, and push a history entry for links followed inside the copy; (3) no copy at all: stub kind `nosnapshot` "This site can't be shown in Compass" with Search Wikipedia for "<name>" / Try Again and a small Open in Safari link. Direct and archived pages load over the visitor's own connection (the site / the Archive see their IP). Compass accepts `__compass` messages only from relayed (opaque-origin) frames: direct frames are ignored entirely. Find, Save Page to Drive need the relay. The first bookmarks (DuckDuckGo, HN, BBC, wttr.in...) are swapped once (`prefs.bookmarksVersion`, `migrateBookmarks`) for Wikipedia, Featured Article, Wiktionary, Wikivoyage, OpenStreetMap, Space Jam (1996, archive), Cameron's World (framable), The First Website, Zombo.com. The `alwaysReal` preference and its menu items are gone.
    - **"True internet" (the code default since 2026-10-04, decided with the owner, who knows Render's AUP clause on bypassing network restrictions and accepts it):** `WEB_RELAY` unset = `on`: signed-on 98 Messenger accounts browse ANY public site live through the relay and search with DuckDuckGo's HTML page (`html.duckduckgo.com/html/?q=`, light and relay-friendly; checked live); guests keep the allowlist through the relay and see every other site straight from the site or as a saved copy with a slim bar **"Sign on to browse this site live. Sign On / Get a Screen Name"** (no interstitial; `why: "signon"`; when the Archive has no copy either, a `signon` stub). Signing on (from the bar, Compass's SignOnDialog, or 98 Messenger) reloads every waiting tab (`t.why === "signon"`) live. `WEB_RELAY=allowlist` (everyone only the allowlist; also any unknown value) and `0`/`off` still work as switches.
    - **Routing table** (Compass.jsx `resolveView`): month closed (`session.closed`) -> everyone without the relay, bar "Live browsing resumes on <the 1st>"; guest + allowlisted -> relay; guest + other site -> direct/saved copy + sign-on bar; signed on + any site -> relay; today's allowance used (`used >= limit` or `session.dayFull`, which also covers the whole relay's / all guests' day) -> direct/saved copy + "Live browsing resumes tomorrow"; a relay stub `budget`/`monthly`/`signon` mid-browsing does the same (and `refreshUsage()` so the next pages skip the relay); the site answers the server with a robot check -> relay stub `siteblocked` -> direct/saved copy with "This site blocks the 98ish server"; blocked site -> a stub "Compass doesn't open this site" (no direct frame, no saved copy: `/api/web/frame` answers `blocked`). Searches use Wikipedia for guests and whenever the session is closed/dayFull.
    - **Safeguards (2026-10-04):**
      - Bandwidth, measured with real Chrome through the local relay against the real internet (scratchpad `web5/measure.mjs`, first view of a page / a second page on the same site; relayed bytes incl. headers as counted by the relay): Hacker News 11/12 KB, DuckDuckGo results 10/10, Simon Willison's blog 29/27, BBC News 70/65, old.reddit 69/69, Wikipedia 88/75, GitHub repo 94/59, Guardian 186/129, NPR 247/205, IKEA category 281/246, MDN 290/282 (its fonts refuse other origins, so they're relayed), Allrecipes 326/325. **Average about 130 KB relayed per page view** (the sites themselves sent 2.6 MB per page straight to the browser). Before the stylesheet/font redirects it was 280 KB (NPR 680, GitHub 438); browsers don't reuse cached relayed stylesheets across pages because an opaque-origin frame gets no shared HTTP cache, so every page re-fetches them. So `WEB_MONTHLY_MB` 1000 is roughly **7,500 live page views a month** (about 250 a day for everyone together), and the per-account day (`WEB_DAILY_MB`, now **25**) about 190 pages. The relay's own XHR/fetch (`/x/`) stays relayed (CORS; also keeps "Relay Pictures Too" private).
      - Caps never shut Compass off: the session reports `dayFull` and `resumes`; budget/monthly stubs fall back (above). Messenger and the rest of 98ish are never cut.
      - Blocklist (`server/web/blocklist.js`, `blockedSite(host, ownerList)`): `WEB_BLOCK_HOSTS` (owner, with subdomains) plus a compact built-in list by category: malware/phishing TEST and sample sites (testsafebrowsing.appspot.com, eicar.org, wicar.org, malware-traffic-analysis.net...), adult (the biggest ~35 hosts, `.xxx/.porn/.adult/.sex/.sexy` TLDs, host-name words porn/xxx/hentai/nsfw/xvideo/xhamster/onlyfans/chaturbate...; NOT "sex" alone, so Sussex/Essex pass), piracy (Pirate Bay, 1337x, YTS, libgen, Z-Library, Sci-Hub, Anna's Archive, streaming mirrors...), other proxies/Tor gateways. A full public-domain adult list (Block List Project, Unlicense) is hundreds of thousands of hosts, too big; limits: innocent-named sites get through, a harmless name containing a keyword is refused. Checked on every hop via the guard's `denyHost` (relay, redirects before the 302 goes out, `/check`, `/frame`).
      - Report This Page (Tools menu; phone menu sheet): `POST /api/web/report { sid, url, note }` -> MongoDB `webreports` `{ account, guest, host, url, note (1000 chars), time, expiresAt }`, TTL 90 days, 10 per hour per session key, nobody notified. The owner reads them in Atlas/mongosh: `db.webreports.find({}, { _id: 0, host: 1, url: 1, note: 1, time: 1 }).sort({ time: -1 })` or counts per host `db.webreports.aggregate([{ $group: { _id: "$host", n: { $sum: 1 } } }, { $sort: { n: -1 } }])` (chosen over an owner-token endpoint: no new auth surface).
      - First-use notice for signed-on users (once per account, `prefs.liveNoticeFor`): "Pages you open live are fetched by the 98ish server. Don't use Compass for anything illegal or to get around a network's rules. Some sites block it; then you'll see a saved copy." Guests keep the older first-run notice (`noticeSeen`).
      - 7-day log (`server/web/records.js`): MongoDB `weblog` `{ _id: "<account>|<host>|<day>", account, host, day, bytes, expiresAt = day + 8 days }` with a TTL index; only signed-on accounts (guests reach only the allowlist); host names only, never paths/queries/contents; written behind every 10 s and on SIGTERM. Abuse question: `db.weblog.find({ host: /example\.com$/ }).sort({ day: -1 })`. Mentioned in Help (`compass`, `privacy-server`, `delete-account`) and About Compass.
      - Delete My Account: eraser step `compass` (`web.eraseAccount`): the account's `weblog` rows, `webreports`, `webusage` counters `u:<key>` (`counters.forget`), relay sessions and cookie jar; also listed in `DeleteAccount.jsx` WHAT_GOES.
      - `/api/web/status` (numbers only) adds `day`, `pagesToday` (relayed HTML pages today, counter `day|pages|<day>`), `relayTodayMB`.
    - **Guests vs signed on (`WEB_RELAY=on`):** the rest of 98ish needs no account; only Compass's relay does, and it reuses the 98 Messenger screen name. Guests (no token) get a relay session limited to the guest allowlist (`GUEST_ALLOW` in `server/web/index.js`: wikipedia.org, wikimedia.org (upload/commons images), wiktionary.org, wikivoyage.org, wikibooks.org, wikiquote.org, openstreetmap.org, example.com, with subdomains; NOT archive.org, whose Wayback Machine would reach any site; the 98ish hosts are always refused). The server enforces it on every relayed request, subresource and `/x/` script request, on every redirect hop (refused before the 302 goes out) and in the frame check's own redirect following (guard.js `allowHost`). A refused page is a `kind: "signon"` stub; Compass also checks first (session `allow` list) and shows "Sign on with your 98 Messenger screen name to browse other sites" with Sign On / Get a Screen Name, which open Compass's own `SignOnDialog` (AimContext `signOn`, same account; the Buddy List opens minimized) and the waiting tabs reload; the prompt also has "Show It Without Signing On" (straight from the site or a saved copy) and only a small Open in Safari link. Guests' omnibox searches go to Wikipedia.
    - **Relay safety model:** sessions belong to a signed-on 98 Messenger account or a guest address (`WEB_GUESTS=0` refuses guests entirely); a session lives in memory, is bound to the client address (cf-connecting-ip on Render) and ends after idle time. SSRF guard (`guard.js`): http(s) only, ports 80/443/8080/8443, no credentials in URLs, no local names, no own host names, every DNS answer must be public unicast (IPv4 + IPv6 incl. mapped/NAT64/6to4/Teredo/ULA/link-local/metadata), and the socket connects to the checked address (no second lookup, so no DNS rebinding); redirects go back to the browser as relay URLs so every hop is checked again. **Isolation (audited 2026-10-04):** relayed documents come from nine8ish.onrender.com, which is also the API origin, so they must never run as it: pages get `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-modals allow-pointer-lock` (no allow-same-origin, no top navigation, no allow-popups-to-escape-sandbox, which used to be there and would have let an unsandboxed popup navigate the 98ish tab through `opener.top`), and Compass's `<iframe sandbox>` matches (`RELAY_SANDBOX`/`DIRECT_SANDBOX`, neither escapes). Every other `/api/web` answer (JSON, scripts, pictures, errors, redirects, preflights) gets a script-less `sandbox` CSP + nosniff from a router middleware. CORS on the relay is `*` and never `Access-Control-Allow-Credentials` (it used to echo the origin with credentials); `inject.js` makes pages' fetch/XHR/EventSource leave credentials out and gives them in-memory localStorage/sessionStorage (methods on the prototype) and document.cookie (the server jar). Service-worker script requests (`Service-Worker` header, `sec-fetch-dest: serviceworker|sharedworker`) are refused; site headers reach the browser only through `PASS_BACK` (never Set-Cookie, Clear-Site-Data, Service-Worker-Allowed, Link, Refresh, CORS, CSP, COOP...: `NEVER_PASS`). The rest of the server refuses `Origin: null` (`server/web/origins.js`: Express middleware after `/api/web`, socket.io `allowRequest`); no 98ish API authenticates by cookie (all bearer tokens), so there are no ambient credentials to steal anyway. Compass's message listener accepts only its own tab frames, from origin `"null"` for relayed tabs, never its own origin, in a fixed shape; it sends frames only find/findClear/zoom/stop. No separate hostname is needed: an opaque origin has no storage, cookies or service worker, and onrender.com is on the Public Suffix List (nine8ish.onrender.com is its own site, unrelated to 98ish.vercel.app). Cookies stay in a server-side jar per account and are sent first-party only (`<tok>` = HMAC(session, site), so one site's page can't use another site's cookies). The person's cookies/Authorization and forwarding/fetch-metadata headers are never forwarded. Limits: per-minute rate, concurrency, response size, daily bytes per account / guest / all guests / whole relay, monthly caps, timeouts; video/audio aren't relayed.
    - **Usage kept across restarts** (`server/meter/counters.js`): counters `{ scope, id, window }` (`day|u:<account>|2026-10-04`, `day|g:<hmac of address>|...`, `day|relay|...`, `day|guests|...`, `month|compass|2026-10`, `month|server|2026-10`) in MongoDB collection `webusage` (`_id` = the key, `n`, `expiresAt` with a TTL index: days 3 days, months 70 days). Write-behind: adds go to memory and are flushed as one `$inc` bulkWrite every 5 s and on SIGTERM/SIGINT (server.js, 3 s max); a counter is read back on first use (`ensure`) and never flushed while it is being read. Guest addresses are stored only as HMAC-SHA256 with `WEB_SECRET`, else a key derived from `MONGODB_URI` (stable across restarts, not stored in the database). If the counters can't be read back (MongoDB down after a restart), the relay refuses with a `kind: "unavailable"` page (fails closed) while sessions, `/status` and the rest of 98ish carry on; mongoose commands aren't buffered, so it fails fast. Per-minute rate limits and the 30-sessions/hour limit stay in memory on purpose: a restart takes longer than their window, and every byte they let through still counts against the persisted budgets.
    - **Monthly traffic meter** (`server/meter/meter.js`, wired in server.js): every TCP socket of the HTTP server (Express, socket.io polling and websockets, the relay) is tracked from `connection`; its `bytesWritten` is sampled every 10 s and settled on close into `month|server|YYYY-MM` (UTC calendar month, as Render bills). Compass closes for the rest of the month when that reaches `WEB_MONTHLY_TOTAL_MB` (3000) or Compass's own relayed bytes reach `WEB_MONTHLY_MB` (1000): relay answers 503 `kind: "monthly"` ("Compass has used this month's data allowance; it's back on November 1"), the session says `closed: <ISO date of the 1st>` so Compass shows its resting page itself (frameable sites still load straight from the site, with a notice); Messenger and everything else are never cut. A warning is logged once a month above `WEB_MONTHLY_WARN_MB` (4000). `GET /api/web/status` (public, numbers only): `{ mode, month, totalMB, compassMB, capMB, compassCapMB, open, reopens }`. The meter counts Node's bytes (no TLS framing; Render's edge may count a bit differently) and only from when it was deployed, hence the wide margin under 5 GB.

    - **Render's terms (checked 2026-10-04):** neither the Acceptable Use Policy (render.com/acceptable-use, modified 2025-08-22) nor the Terms (render.com/terms, modified 2026-07-10) mentions proxies. Relevant: AUP "Bypass Access or Usage Restrictions ... including using the Service to bypass network restrictions or access non-public services" and "Abuse Network Resources or Service Capacity"; free tier "Render may suspend a Free web service that initiates an uncommonly high volume of traffic over the public internet" (render.com/docs/free). Hence: sign-on beyond a small allowlist, SSRF guard, small byte budgets, and the `WEB_RELAY` switch (`allowlist` or `0` is the conservative choice).
    - **Known limits:** some sites block the relay: a 401/403/429/503 page with `cf-mitigated`/`x-amzn-waf-action` or a robot-check title ("Just a moment", "Access denied", captcha...) becomes a `siteblocked` stub and Compass shows the site straight from the site or as a saved copy with "This site blocks the 98ish server" (Stack Overflow's Cloudflare check, checked live); big app-like sites partly break (BBC News showed "Application error", old.reddit a "Welcome to Reddit" wall); sites see the server's IP for pages (Cloudflare/bot checks may block some; DuckDuckGo blocks headless Chrome's user agent, real browsers are fine); WebSockets, service workers and the page's own localStorage persistence don't work relayed; big JS apps (Google, Facebook, banks) and video need the real browser; cookies are lost when Render restarts; in direct-assets mode sites see the person's IP through pictures/scripts.
