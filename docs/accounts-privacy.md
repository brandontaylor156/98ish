# Accounts and privacy (Delete My Account, privacy help)
Moved from CLAUDE.md on 2026-10-05.

## Accounts and privacy
- **Delete My Account** (98 Messenger > My AIM, Control Panel > Passwords and Users > User Profiles; Sign On offers "Finish deleting..." for a half-done one):
  - Server: socket `aim:deleteAccount { screenName, password }` in `server/aim/index.js` (password re-checked with the sign-on failure limits; must be signed on as that account unless it's already marked `deleting`). Order: mark `deleting` (+ the couple ids/partners for a retry, `remember: []`; sign-on and remembered sign-on refused) -> sign off every session (other windows get `aim:kicked { deleted: true }`) -> `eraser.run(ctx)` -> drop the name from everyone's Buddy Lists/blocks (`store.forgetEverywhere`, live sessions get `aim:accountGone { groups, blocked }`) -> forget warnings/bot memory -> delete the user doc (the name is free). A failed step answers `{ retry: true }`; asking again resumes (every step is idempotent).
  - `server/account/index.js`: `createAccountEraser()` (`addContext`, `add(name, fn)`, `run`) and THE INVENTORY: every collection, what deleting does, and the privacy rules. Steps wired in `server.js` in order: push, messages (98 Messenger history), im media, albums (Shared Albums), drive (sync + legacy `drives`), contacts, notes, locations (Buddy Locator), pickleball (Pickleball 98's Real Games), mail, puzzles, quiz, homepages, guestbook, games (Tetris ranks + co-op towns via `net.eraseAccount`), calendar, dollhouse, town, couples, gamechat. Each module exposes `eraseAccount(ctx)` (ctx `{ key, screenName, coupleIds, partners }`) on its router/service. **A new module that stores anything per account must add an eraser step and a line to that inventory** (and to Help's privacy topics).
  - 98 Messenger's module (`server/aim/index.js`) adds its own steps: "shared documents" (Come Over, `ydocs.eraseAccount`) and "vb98 programs" (Visual Basic 98's programs in a message, `vbapps.eraseAccount`: they leave every shared program, one nobody else is in is deleted, Shared values they set stay; `docs/vb98.md`).
  - Rules: mail they sent stays in recipients' mailboxes with From/To/Cc "(deleted account)" (`DELETED_NAME`, not a valid screen name); couple things are purged at once for every pairing (incl. pending/ended) and the partner gets a neutral one-time notice (pair record `status: "notice"`, returned once by GET /api/couples as `notice: "closed"`, client `couple:closed` toast); shared calendars: they leave, owner role moves, their events/comments/activity go; town: their notes/hearts go, gifts/help they gave are anonymized; guestbook entries are tied to an account (`owner`, never shown) only when signed on (the client sends the Bearer token).
  - Client: `aim/DeleteAccount.jsx` (window app `aim-delete`, kept open across the sign-off; list of what goes, erase-this-device checkbox default on, screen name + password, "Delete Account" is `type=button` so Enter never deletes; then "Your account was deleted"), `AimContext.deleteAccount/openDeleteAccount`, `utils/account.js forgetAccountOnDevice({ key, eraseLocal })` (push unsubscribe + inbox cache, sync prefs/token/bookkeeping via `forgetSyncAccount`, contacts link via `forgetContactsAccount`, notifications via `forgetNotifications`, mail index, town/dollhouse caches, profile screen-name links; with `eraseLocal` `fs.eraseThisDrive()` + every `keysOf(currentUserId())` localStorage key, then reload).
- Wave 2 (uploads kept as they are, the music + video library, PDF Viewer) added **no server store**: big media stays in the device's drive database, so there's no new eraser step; Help's privacy-device table names the new local stores (drive Blobs, `98ish.videos`, video posters in `98ish-music`) and privacy-third-parties lists pdf.js from jsDelivr.
- Wave 2 part 2 (Snipping Tool, clipboard history) added **no server store** either. The clipboard history is device-only per user: IndexedDB `98ish-clipboard` (`-<id>` for extra profiles), deleted by `onUserRemoved`, and `forgetAccountOnDevice` erases it (pinned items too) on every Delete My Account, not only with "erase this device" (copies may hold the account's messages). Help's privacy-device table lists it, privacy-delete says how to clear it, delete-account mentions it, and privacy-third-parties lists modern-screenshot from jsDelivr (Snipping Tool's screen copier; snips themselves never leave the device).
- **Privacy help**: `help/topics/support.js` book "privacy": privacy-overview, privacy-device, privacy-server (per-store table: kept how long, who sees), privacy-third-parties (Vercel, Render/Atlas, push services, Google STUN, optional TURN, YouTube relay, Wayback relay, Wiktionary), privacy-couples, delete-account, privacy-delete. Derived from the code; update them with each feature.
- Wave 3 (Scanner 98, version history, desktop gadgets) added **no server store**. Scanner 98 works on the device only (its PDFs are ordinary drive files). Version history is a per-user IndexedDB database (`98ish.versions` / `98ish.u.<id>.versions`), dropped by `onUserRemoved`, erased by `forgetAccountOnDevice` with "erase this device", and it expires by itself after 7 days. Gadgets are one localStorage key (`98ish.gadgets`, per user) and reuse the programs' own stores. Help: privacy-device (a versions row; gadgets in the localStorage row), privacy-delete (a previous-versions row), delete-account (previous versions erased with the device).
- Wave 4 (passkeys, Sheets 98, Unit Converter, Color Picker, QR Code, Dice & Coin): **one new server store**, 98 Messenger passkeys (MongoDB `aimpasskeys`, `server/aim/passkeyStore.js`): eraser step `passkeys` (added by `server/aim/index.js` after the server.js steps; every record of the account) and a line in the inventory in `server/account/index.js`; Delete My Account's list says the passkey stays in the device's password manager but no longer signs on. Help: privacy-server (a Passkeys row), privacy-delete (a passkey row), delete-account (passkeys erased), the new `passkeys` topic. The rest is device-only: Sheets 98 workbooks are ordinary drive files (type `sheet`, or `.csv` text), Unit Converter / Color Picker / Dice & Coin remember their last choices in localStorage (`98ish.units`, `98ish.colorpicker`, `98ish.dice`, per user through the storage seam), QR Code keeps nothing (pictures it saves go to My Pictures). privacy-third-parties lists jsQR from jsDelivr (QR Code's reader on devices without `BarcodeDetector`; the camera picture never leaves the device).
