# The 98ish drive, persistence and file sync
Moved from CLAUDE.md on 2026-10-05.

## Storage and sync
- **Vercel Blob checked against the real store (2026-10-04):** from a page at https://98ish.vercel.app in real Chrome, a presigned PUT (headers only `x-api-version`, `x-vercel-blob-access`, `x-content-type`: Vercel's CORS allow-list doesn't include `x-add-random-suffix`/`x-allow-overwrite`, and the signed URL already pins them) and a presigned GET work (`Access-Control-Allow-Origin: *`); unsigned GETs, oversize PUTs and overwrites are refused; `head()` reports the size. Scripts: scratchpad `blob-smoke.cjs`, `blob-browser.cjs` (token pulled with `vercel env pull` into a temp file, deleted at once, never printed).
- **The drive** (`utils/fs.js`, `utils/driveStore.js`): the synchronous tree API is unchanged, but the drive is kept in IndexedDB (database `98ish-drive`: `meta` holds the folder index with small files inline, `contents` holds big texts keyed by a content hash, so copies share storage and unreferenced contents are deleted in the same transaction). `main.jsx` renders nothing until `fsReady` (a "Loading your files..." screen after 300 ms). `navigator.storage.persist()` is requested at start.
  - Big contents load on demand: `file.textContent` returns "" until loaded (and starts loading); use `await readContent(file)` (or `peekContent`) for anything that sends, edits or copies contents; `file.loaded`, `file.size`, `file.head` (first 48 characters: what kind of data URL), `file.textLength`, `file.thumb` (192 px JPEG of big pictures, made in the background) work without loading. Memory cache: 48 MB of text on phones, 160 MB on computers.
  - `saveNow()` and `writeAndSave()` are async (resolve false on a full disk; callers await them). Saves run 40 ms after a change: a browser drops IndexedDB writes started while a page closes, so the window stays tiny.
  - First start after the update moves the old localStorage drive (`98ish.fs.v1`): one transaction, read back and compared file by file, then marked (`98ish.fs.migrated` + IndexedDB `meta.migration`). The old copy stays 3 days. A failed move changes nothing and is retried next start (meanwhile the old drive works). Without IndexedDB (some private windows) the old 5 MB localStorage drive is used, and `StorageNotice` says so; if IndexedDB was used before but won't open, the drive opens read-only-ish ("changes won't be saved").
  - Drive C: Properties (My Computer) shows used/free/capacity with the Win98 pie (`fileExplorer/DriveProperties.jsx`); Camera and Photos show free space; `DISK_FULL` is the shared "Drive C: is full" text.
  - Backup builds the file in pieces (`writeDriveJson`, `createBackupBlob`); Restore and `importDrive` put everything back if it doesn't fit.
- **Persistence ("photos must PERSIST")**: the device copy can vanish (Safari evicts a site's storage after ~7 days without a visit unless it's a Home Screen app; any browser may evict without `persist()`), so file sync is the safety net:
  - **Sync is ON by default**: `98ish.drive.sync` prefs carry `told`; nothing saved (or an old-version `enabled:false` without `told`, which every sign-off used to save) means on, and the first sign-on sets `told` and `turnedOn`, which `backup/DriveSync.jsx` shows once as a 98 dialog ("File sync is on", OK / Settings...) plus a Notification Center item. Turning it off in Backup is remembered (`told: true`). Old browser suites that click `label[for=bk-sync]` to turn sync ON must now click only if `#bk-sync` isn't checked.
  - A change uploads ~4 s later (`PUSH_DELAY_MS`) and on `visibilitychange`; a new device (or a wiped one) pulls everything at sign-on.
  - `navigator.storage.persist()` is asked at start and again on the first `pointerdown` if refused; the answer is `storageInfo().persisted`, shown in Drive C: Properties and Control Panel > Storage (with an iPhone 7-day hint when not on the Home Screen).
  - **Guests**: `utils/keepSafe.js` (pure, `keepSafe.test.js`) + `shared/KeepSafe.jsx` (`useKeepSafe`, `<KeepSafe place>` note with Sign On... / Backup... / close for 30 days, `98ish.keepSafe`): Camera after a photo, Photos, My Computer's status bar (`.fxKeepSafe`), Control Panel > Storage ("Keep your files safe").
  - Capacity: photos are JPEG <= 2048 px and `MAX_CHARS` 560,000 (~400 KB; `photos/photoMath.js`), stored as binary on the server, so 100 MB is ~250-300 photos per account and a couple fits in 200 MB of Atlas's 512 MB; `DRIVE_SYNC_TOTAL_MB` guards the rest.
- **File sync** (`utils/driveSync.js`, decisions in `utils/syncPlan.js`; server `server/drive/sync.js` + `syncStore.js` at `/api/drive/sync`): per-file sync of chosen top-level folders (default My Documents, My Pictures, Desktop; never Programs/Windows/Bookmarks) for the signed-on 98 Messenger account. Entries are keyed by path with a server revision counter; devices pull changes since their last revision, upload missing contents (checked against their hash), then push changes with the revision they were based on. Both changed: both kept, this device's copy renamed "name (from iPhone)". Deletes are tombstones and land in the other device's Recycle Bin. Settings and online usage are in Backup ("Sync with 98 Messenger"); status in the taskbar tray (`backup/SyncTray.jsx`) and My Computer's status bar.
  - On by default: a device with nothing saved turns sync on at its first sign on and says so once (`told`). A device that saved "off" under an older version (which saved "off" on every sign off, chosen or not) is NOT turned on silently: the next sign on asks once ("Turn on file sync?" Turn On / Not Now, `ask` in the prefs, `answerSyncAsk`); either answer is final (Backup can still change it). Browser test `del-ask.mjs`.
  - Signing on gives the device its own sync token (POST `/device`, stored hashed, 60 days, 10 per account), so a device bumped by a sign-on elsewhere keeps syncing; signing off on purpose or turning sync off forgets it.
  - **Online storage bucket** (`server/drive/bucket.js`, on with `BLOB_READ_WRITE_TOKEN`; `@vercel/blob` SDK): contents go to Vercel Blob at `u/<HMAC of account>/<contentKey>` (private, content-addressed, type always `application/octet-stream`; the real type is in the record) and MongoDB keeps only records (`syncblobs` with `store: "bucket"`, `path`, no `data`). `/state` says `direct: true`; the client (`driveSync.js` `uploadDirect`/`downloadDirect`) does `POST /upload` (quota + 30-min reservation, presigned PUT: size and type pinned, no overwrite, 10 min) -> PUT -> `POST /commit` (server `head()`s the size), and `POST /urls` (presigned GETs, 5 min, own account only, asked for 20 at a time). Anything that fails falls back to the old `/blob` routes, which also work with the bucket (server reads/writes it). FREE ONLY: every op is counted in MongoDB `blobusage` (one doc per UTC day) BEFORE it happens, against rolling 31-day budgets under Vercel Hobby's free limits (1 GB stored, 2,000 advanced ops, 10,000 simple ops, 10 GB transfer); when one is used up, uploads/downloads answer 429 "Online storage is resting until <date>" and files wait on the device. Vercel saying the store is suspended rests everything a day. Background upkeep (every 10 min, 1 min while busy; 70% of each budget): expired reservations dropped, old MongoDB contents moved 10 at a time (first 20 read back and compared, the rest size-checked; MongoDB copy kept 7 days, then `data` unset), weekly list for stray objects (no record, over a day old). Delete My Account / Delete Online Files delete objects by their recorded paths (del is free). Public numbers: `GET /api/drive/sync/status`. Hobby usage is shared with the website, so the budgets leave room. Presigned GETs from a browser to `*.private.blob.vercel-storage.com` are not yet tried on real Vercel: if CORS blocks them, the client falls back to `/blob` (server egress) automatically.
  - MongoDB collections `syncaccounts`, `syncentries`, `syncblobs` (data URLs stored as binary, other text deflated; with a bucket only records), `syncdevices`, `blobusage`. Quota and file size from the env vars above; 20,000 entries per account; per-account rate limits and 300 MB upload per 10 minutes. The old whole-drive copies (`drives`, `/api/drive`) still work and are converted into synced files the first time an account syncs.
