# Buddy Locator (Find My Friends, 98ish style) (2026-10-05)

Opt-in location sharing between 98 Messenger buddies on a map. Program "Buddy Locator" (`applets/locator/`, app `locator`, group Internet, also Us; DOS `locator`/`findfriends`), server `server/locate/`, rules `applets/locator/locateCore.js` (pure, shared: the server loads it with a dynamic import like Notes' `notesCore.js`).

## Privacy design
- **Nothing is shared by default.** You share with one buddy at a time, for 1 hour / until local midnight / indefinitely (`untilFor`; the device works out "end of day", the server only sees an end time, null = indefinitely, at most a year). Only people in your Buddy List, or someone who asked you (an ask is consent), never yourself, SmarterChild, unregistered names, or anyone blocking/blocked either way.
- **Only the latest position is stored, never a history.** It's dropped on pause, on Stop, when the last share runs out (sweep every minute, `sweep()`), and the server keeps nothing at all while you share with nobody (`/update` returns `kept: false`).
- **Approximate location** (`coarse`): snapped to a ~1.1 km grid (`coarsen`: 0.01 deg latitude, longitude step widened by 1/cos(lat) so cells stay square, `acc` >= 1000) **on the device before sending** (utils/locate.js) and again on the server. The same spot always lands on the same cell. Arrive/leave alerts never fire for positions vaguer than 500 m.
- Blocking hides you at once (state and live relay both check blocks both ways via `aim.sessions`/`aim.store.find`).
- Tray indicator: `applets/locator/LocatorTray.jsx` in the taskbar tray (also on phones) whenever any share is active: blue arrow sending, grey paused, flashing when updates need a tap. Menu: who sees you, Resume location updates, Pause/Resume Sharing, **Stop Sharing Everywhere**, Open Buddy Locator.
- Delete My Account: eraser step `locations` (removes the record, `pullMentions` takes the account out of everyone else's shares/asks/watches, viewers get `loc:gone { reason: "deleted" }`); inventory line in `server/account/index.js`; Help privacy topics (privacy-overview, privacy-server table row + "who can see", privacy-third-parties: OpenFreeMap, delete-account, privacy-delete "Your location").

## Server (`server/locate/`)
- Store (`store.js`): one record per account in MongoDB `locations` (memory without MONGODB_URI): `{ key, name, shares: [{ to, name, until, since }], paused, coarse, pos: { lat, lon, acc, at, coarse? } | null, places: [{ id, name, lat, lon, r }], watches: [{ id, who, place, on, inside }], asks: [{ from, name, at }], changedAt }`. Own edits replace the record (`put`); things other people change are targeted (`addAsk`, `removeAsk`, `setInside`, `pullMentions`) so they never overwrite the owner's edits. Indexes on `shares.to`, `shares.until`, `asks.from`, `asks.at`, `watches.who`.
- HTTP (`index.js`, all POST, `Authorization: Bearer <98 Messenger token>`, like Notes): `/state`, `/share { to, until }`, `/unshare { to } | { all }`, `/pause { paused }`, `/settings { coarse }`, `/update { lat, lon, acc }`, `/ask { to }`, `/answer { from, accept, until }`, `/places { places }` (replace; a moved/resized place resets its watches to "not known"), `/watch { who, place, on: arrive|leave|both|off }` (only for someone sharing with you).
- Live on the 98 Messenger socket: `loc:pos { key, name, pos }`, `loc:gone { key, reason: stopped|paused|ended|deleted }`, `loc:shared { key, name, until, pos }`, `loc:ask { from, name }`, `loc:alert { key, name, place, event, at }`, `loc:changed` (your own devices re-read `/state`).
- Geofences run on the server on each update of the sharer, per viewer watch (`fenceStep`: arrive within r, leave past r + max(30 m, r/4); the first fix after a watch starts only sets in/out; fixes with acc > 500 m decide nothing). Alerts: `loc:alert` + push category **`places`** (new in `server/push` CATEGORIES and the Notifications settings list; DND holds it server-side like other categories), deep link `/?open=program&name=Buddy%20Locator`. New shares and asks push too.
- Caps / budgets: shares 50, places 20, watches 40, asks 20 (7 days) per account; ~1-3 KB per record, so even 1,000 accounts is ~3 MB of Atlas. Rate limits per account per 10 min: 400 requests, 60 `/update` (the app sends at most every 30 s), 30 asks an hour; bad tokens 30 per IP per 10 min. Traffic: ~200 B per update per viewer, nothing against Render's 5 GB.

## Client
- `utils/locate.js` (module store outside React, `useLocate()`; nothing in localStorage, so the storage seam has nothing to do): session from AimContext (next to Notes' `setSyncSession`), `refresh()`, actions (`shareWith`, `stopSharing`, `stopAll`, `setPaused`, `setCoarse`, `askToSee`, `answerAsk`, `savePlaces`, `setWatch`), `locateMe()` (one fix for this device only: "Me", place "Where I Am"), socket handlers (`onPos`, `onGone`, `onShared`, `onChanged`). While any share is active and not paused it runs `watchPosition` (high accuracy, maximumAge 15 s): `shouldSend` = first fix, or >= 30 s and >= 50 m since the last sent, or >= 2 min (a 30 s ticker resends the last fix so "2 min ago" stays fresh while standing still; a fix that moved far enough but came too soon is sent when the 30 s are up). After a reload it restarts by itself only if `navigator.permissions` says geolocation is granted, else `geo.state = "needs-tap"` (tray flashes, app shows Resume): iOS wants the prompt from a tap. Dev hook `window.__locate`.
- `LocatorBridge.jsx` (desktop, inside the Messenger provider, lazy): socket events -> store; `notify({ app: "locator" })` + a 98 pop-up (`.locToast`) unless `interrupts("locator")` says Do Not Disturb.
- `Locator.jsx` (+ `Locator.css`): baseline = Share My Location... (buddy + how long), status line ("Sharing with ..."; "Updates while 98ish is open. Last sent ..."), ask banners (Share 1 Hour / Always / Not Now), the map, the people list ("2 min ago · 1.2 mi away · approximate"), a selected buddy's card (Message, Call (`placeCall`), Directions (Apple Maps on Apple devices, else Google Maps), Notify Me...). More options: who you share with (Stop each), Pause sharing, Stop Sharing Everywhere, Approximate location, Ask to see a buddy, Places (Add a Place: Where I Am / Middle of Map, 100 m-1 km). Phones: map on top (46%), list below. `.loc` is `calc(100% - 25px)` like Notes/Casino.
- `LocatorMap.jsx` (lazy): MapLibre GL 5 (`maplibre-gl` dependency, its own ~1 MB / 273 KB gzip chunk, only loaded when Buddy Locator opens) + OpenFreeMap's `liberty` style (free, no key, no limits; the style carries the OpenFreeMap / OpenMapTiles / OpenStreetMap credit). OSM's own tile servers aren't used (their policy doesn't suit apps). HTML pins (98 square with initials + name tag; "You" is a blue dot), accuracy and place circles as GeoJSON layers, rotation off, the map follows the selected buddy, zoom buttons in 98 clothes. MapLibre's `.maplibregl-map { position: relative }` must be overridden (`.locMap.maplibregl-map`) or the canvas has no height. No WebGL: an explanation, the list still works. Dev hook `window.__locatorMap`.
- Pickleball venues as places (2026-10-08): see "Venue places" below.

## Venue places (2026-10-08)
Pickleball 98's real venues are ready-made places, so arrive/leave alerts work for them ("Rosie arrived at Los Cab").
- **How:** **Notify Me...** lists your places and, under **Pickleball courts**, every real venue that isn't one of them yet (`venuePlaceChoices`). Picking one and pressing OK first adds it to your places (`/places`), then sets the watch. **Add a Place...**'s "Or a pickleball court..." list makes the same place (with its id, so it isn't offered twice). The alert, push and toast are the ordinary place ones (`fenceStep`, category `places`).
- **Data (no duplicates):** `pickleball/play/meet.js` `venuePlace(id)` builds `{ id: "pb<venue>", name: short name, lat, lon, r }` from `park/venues/index.js` `VENUE_LIST` (the courts' middle). Size by venue: indoor halls 100 m, big outdoor clubs (30+ courts: Los Cab, Newport) 300 m, the rest 150 m. The old dialog read `pbclub/clubCore.js`'s copy of the coordinates; it now uses VENUE_LIST too.
- **Privacy / caps:** opt-in (nothing is added until you pick one); a venue place is one of your 20 places in your own `locations` record, removable under More options > Places like any other; nothing new is stored, so there's no new eraser step (the `locations` step already deletes places). The server now keeps an id given twice only once (a second copy gets a new id). Arriving still needs a position within 500 m accuracy (approximate sharers never trigger it).
- **Tests:** `server/locate/test/locate.test.js` "venue places" (every venue makes a valid place kept exactly as made, one id each, no Riverside; choices leave out what you have; over HTTP: the same venue twice keeps one id, watch Los Cab, arrive -> `loc:alert` "Los Cab" + push "Alice arrived at Los Cab", leave; the 20-place cap). Browser (scratchpad `r8loc.mjs`, two iPhone-sized contexts with geolocation): Alice shares with Bob; Bob's Notify Me... lists the 8 courts, picking Los Cab makes the place (`pbloscab`, 300 m) and the alert line "When Alice arrives at Los Cab"; Alice's position moves into Los Cab and Bob's pop-up says "arrived at Los Cab"; no sideways scroll. Screenshots `shots/r8-loc-*.png`.
- **Left:** Venue Finder courts aren't offered as places (they'd need the kept list from Pickleball 98's prefs on that device); a real iPhone still only reports location while 98ish is open.

## iPhone limits (also in Help)
- A web app can't report location in the background: updates stop when 98ish is in the background or the screen locks, and resume when it's open again (Resume if asked). The UI says "Updates while 98ish is open".
- No battery level (not available to web pages on iOS).
- The location prompt must come from a tap: Share, Resume, Me, Where I Am all are taps.

## Live Venue Presence (2026-10-06)
Ties Buddy Locator to Pickleball 98's real venues: a buddy who shares their location with you and is physically at Los Cab, Newport TPC, Wolf + Bear, Whittier Narrows, Paseo Club, Sinaloa MS or California SMASH shows up at that venue in My Park, "here for real".
- **Rules:** `client/src/components/applets/pickleball/park/presence.js` (pure, shared with the server). A venue record is `{ id, short, origin, bounds, courts }`: origin and courts from the venue spec (`park/venues/<id>.json`), bounds from `server/park/venues.json`. `presenceStep(venues, prev, pos)` -> `{ id, area }` (area `c<i>` = the nearest spec court within 30 m, else `site`) | `{ id, nearby: true }` (approximate location within 1.5 km of a venue's middle: never placed) | `null`. Arriving needs the bounds themselves; leaving needs 40 m past them (`LEAVE_MARGIN`); fixes vaguer than 150 m (`MAX_ACC`) decide nothing. `spotFor(courts, area, slot)` stands people beside their court (slots 0-3 / 4-7 the long sides, 8-15 past the baselines). `friendsAt`, `badgeText`.
- **Server:** `server/locate/presence.js` (`createPresence`, venue table loaded once from the spec files) is wired into `server/locate/index.js`: `/update` steps the sharer's presence and sends `venue` with `loc:pos` (and returns it), `/state` adds `venue` to each friend and to `me`; the answer lives in a Map in memory (for the hysteresis) and is forgotten with the position (pause, stop, last share ended, Delete My Account). **Nothing new is stored**, so there's no new eraser step; viewers are exactly the people who already get the position (same block checks). Riverside is never a venue. Venue Finder (live OSM) venues aren't included yet.
- **Client:** `utils/locate.js` keeps `friends[].venue` / `me.venue`. Pickleball.jsx: `friendsAt(loc.friends, parkWorld.venue)` -> `world.setReal([{ key, name, area }])` (`park/world.js`: bodies with `real: true`, placed at the first `spotFor` slot the walkable check moves least, facing the court, label kind `real`: "{name} · here for real" with a red pin, sub "Court N"); `RealFriendsBar` (park/ParkHud.jsx) at the top of the park (hidden while the intro card is up): Say hi (an IM through `useAim().sendIm`) and Plan a game (leaves the park, opens Real Games with `handoff: { venue }` = New Session there). The venue picker (`FinderPanel` `badges`) shows "N friends here now" plus "N playing in 98ish" from the new `park:counts` request (server/park: numbers only, per real venue). Real Games' SessionView shows "here now" for members physically at the session's venue (friends who share with you, and you) and, when you're there during the session window, a **Check in** button (sets the existing `late: "here"`).
- **Tests:** `node --test client/src/components/applets/pickleball/park/presence.test.js` (8: projection round trip, membership + area, hysteresis, vague fixes, approximate = nearby, court-level snapping, spots, badges); `node --test server/locate/test/presence.test.js` (6, in root `npm test`: the seven venues load, only the shared-with viewer gets `{ id, area }`, court-level only, approximate nearby, gate hysteresis + leaving, pause/stop forget it); `server/park/test/park.test.js` park:counts. Browser: scratchpad `lp/lp.mjs` (vite 5223 with `VITE_SOCKET_URL=http://localhost:8023`, server 8023): Alice (desktop, geolocation on Los Cab court 1) shares with Bob (iPhone emulation): her presence `{ loscab, c0 }`, Bob's picker badge "1 friend here now", Bob's park has her beside court 1 labelled "here for real · Court 1" with the strip, Say hi reaches her as an IM, a Real Games session there shows her "here now" to Bob and offers her Check in (Bob sees it), Stop Sharing Everywhere removes her and the badge, no sideways scroll, no page errors (25 checks). Screenshots `lp/shots/`.
- **Limits:** a real iPhone only reports location while 98ish is open, so "here for real" lasts as long as their 98ish is open (or their last position, until the share ends). Venue Finder venues aren't covered. Placement is at the nearest walkable spot by their court (at fenced banks that's the fence line). The "playing in 98ish" count includes you if you're in that park.
