# Server environment variables and production config (Render)
Moved from CLAUDE.md on 2026-10-05. Never print any value.

- **Env vars (Render), all optional:**
  - `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` + `VAPID_SUBJECT` (`mailto:you@example.com`): Web Push. Generate a pair once with `npx web-push generate-vapid-keys` (never commit it; changing it later makes every device turn notifications on again). Without them push is hidden in the settings ("not set up on this server") and nothing errors. `PUSH_DEBUG=1` logs send counts.
  - Render's free tier sleeps after 15 idle minutes, so scheduled reminders and Our Pet pushes wait until something wakes the server (it then catches up 30 minutes back). A free uptime pinger (cron-job.org or UptimeRobot hitting `https://nine8ish.onrender.com/` every 10 minutes) keeps it awake; one always-on service fits in the free 750 hours a month.
  - `METERED_TURN_APP` + `METERED_TURN_API_KEY`: Metered Open Relay TURN (free account, 20 GB/month). APP is the `<app>` of `<app>.metered.live`; the server fetches credentials, so the key never reaches the browser.
  - Or `TURN_URLS` (comma-separated `turn:`/`turns:` URLs) + `TURN_USERNAME` + `TURN_CREDENTIAL` for any other TURN server.
  - Compass's relay (`server/web/index.js` lists them): `WEB_RELAY` = `on` (the default when unset: members anywhere, guests the allowlist) | `allowlist` (also for unknown values: everyone only the allowlist) | `0`/`off` (no relay: Compass shows every site straight from the site when it allows frames, else as the Internet Archive's copy). `WEB_FRAME_CHECK=0` turns off `GET /api/web/frame` (then every site that isn't relayed shows as a saved copy); `WEB_FRAME_CHECKS_PER_MIN` (1200, all addresses). `WEB_GUESTS=0` refuses guests even for the allowlist (the old `WEB_GUESTS=1` "guests anywhere" is gone). `WEB_GUEST_ALLOW` (comma list replacing the allowlist; `none` empties it). `WEB_DAILY_MB` (25 per account), `WEB_GUEST_DAILY_MB` (10 per guest address), `WEB_GUESTS_TOTAL_DAILY_MB` (40, all guests), `WEB_GLOBAL_DAILY_MB` (100: Render's Hobby workspace includes only 5 GB/month of outbound bandwidth for everything, and with no payment method Render suspends all free services for the rest of the month when it runs out; render.com/docs/outbound-bandwidth, render.com/docs/free), `WEB_RATE_PER_MIN` (300), `WEB_GUEST_RATE_PER_MIN` (120), `WEB_MAX_MB` (12 per response), `WEB_TIMEOUT_MS`, `WEB_CONCURRENCY`, `WEB_IDLE_MINUTES`, `WEB_BLOCK_HOSTS` (sites Compass never opens, with subdomains, on top of `blocklist.js`), `WEB_PUBLIC_URL`, `WEB_BIND_IP=0`, `WEB_SECRET` (keeps site tokens across restarts; also keys the guest-address hashes, else derived from `MONGODB_URI`), `WEB_MONTHLY_MB` (1000, Compass's relay per calendar month), `WEB_MONTHLY_TOTAL_MB` (3000, everything the server sent this month; Compass closes until the 1st), `WEB_MONTHLY_WARN_MB` (4000, log a warning). Usage counters are in MongoDB (`webusage`); cookie jars are in memory. Production needs none of these set.
  - With none set, calls are STUN-only (Google's public STUN): most Wi-Fi works; some cellular/strict NATs can't connect, and the call window then says why after about 30 seconds.
  - `DRIVE_SYNC_QUOTA_MB` (default 100 with contents in MongoDB, 300 with a bucket): synced file contents per 98 Messenger account. MongoDB's free tier is 512 MB in all, so keep it modest.
  - `BLOB_READ_WRITE_TOKEN`: synced file CONTENTS go to the private Vercel Blob store `98ish-drive` (see "Storage and sync"). Budget overrides (defaults are the safe free ones; only lower them): `BLOB_TOTAL_MB` 750, `BLOB_MONTHLY_ADVANCED_OPS` 1400, `BLOB_MONTHLY_SIMPLE_OPS` 7000, `BLOB_MONTHLY_DOWNLOAD_MB` 6144 (rolling 31 days). Optional `BLOB_KEY_SECRET` (HMAC for object names; default derived from the token). Never set `BLOB_STORE_URL` / `VERCEL_BLOB_API_URL` in production (tests point them at the fake).
  - Optional instead: an S3-compatible bucket (Backblaze B2) with `BLOB_S3_ENDPOINT`, `BLOB_S3_BUCKET`, `BLOB_S3_KEY_ID`, `BLOB_S3_SECRET` (+ `BLOB_S3_REGION`); daily budgets `BLOB_DAILY_SIMPLE_OPS` 2000, `BLOB_DAILY_ADVANCED_OPS` 2000, `BLOB_DAILY_DOWNLOAD_MB` 800, total 8 GB. Not tried against real B2.
  - `DRIVE_SYNC_TOTAL_MB` (default 380): all accounts' synced contents together; past it uploads get a 413 "98ish's online storage is full" (files wait on the device), so Atlas never fills up and refuses every write (mail, calendars, accounts).
  - `DRIVE_SYNC_MAX_FILE_MB` (default 12): the biggest single file that syncs.
  - `IM_HISTORY_MAX_DOCS` (default 120000, ~55 MB): saved IMs for everyone together (oldest go first). `MSG_MEDIA_QUOTA_MB` (50 per account per 90 days), `MSG_MEDIA_TOTAL_MB` (200), `MSG_MEDIA_DAYS` (90), `MSG_MEDIA_SHARE` (0.5 of each Blob budget): pictures and voice messages in IMs (see "98 Messenger history").
  - `ALBUM_QUOTA_MB` (40 per account), `ALBUM_TOTAL_MB` (150), `ALBUM_MAX_ITEMS` (2000 records, ~25 MB of Atlas at most), `ALBUM_SHARE` (0.25 of each Blob budget): Shared Albums in Photos (`server/albums`, `docs/apps.md`).
