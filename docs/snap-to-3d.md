# Snap to 3D (3D Viewer 98)

Turn a photo into a 3D model, keep it in `C:\My 3D`, look at it, put it in My Park, make it a desktop toy, or send it in Messenger. Code in `client/src/components/applets/viewer3d/`.

## How it works
- **Make 3D** (3D Viewer 98's button, Photos' Share menu "Make 3D...", Camera's File > "Make 3D from Last Photo..."): a dialog says the photo goes to Hugging Face, then `space.js makeFromPhoto` calls the free Space **microsoft/TRELLIS.2** (MIT code + weights) from the browser with `@gradio/client`: `start_session` → `preprocess_image` (cuts out the subject) → `image_to_3d` (seed 0, resolution 512) → `extract_glb` (decimation 30k, texture 1024) → fetch the GLB. Nothing goes through Render.
- **Bring a Creature to Life** (More options / Model menu): **VAST-AI/AniGen** (MIT; its CUBVH extension is non-commercial but runs only inside their Space): `prepare_input_for_generation` → `generate_preview` → `extract_glb` (simplify 0.95, texture 1024); the rigged GLB is `data[1]`. The viewer plays an idle clip if the model has one, otherwise sways the bones procedurally.
- **Import Model...**: `.glb`, or `.gltf` with embedded `data:` buffers. `core.js validateModel` checks the magic, glTF 2.0, the declared length and the 8 MB cap, with plain-words errors.
- **Shrinking** (`shrink.js`): over 30,000 triangles → three's `SimplifyModifier` (non-skinned meshes; never below 2%), textures redrawn smaller (`textureFor`, floor 256), re-exported as binary glTF with animations; retries with a smaller texture until under the byte cap.
- **Storage** (`store.js`): drive files of type `model3d` in `C:\My 3D` (newest 20 kept), so they ride drive sync and Delete My Account's drive step. No new per-account server store.
- **Viewer** (`scene.js`): orbit (drag/pinch), Tilt to Look (DeviceOrientation, iOS permission on tap), snapshot for Share a Picture (`shareOut`).
- **Place in My Park** (`petLayer.js`, hooked into `pickleball/park/world.js` with 3 lines): your model stands beside you and trots after you (`core.js stepPet`: walk/run toward a spot behind-left of you, rests and turns your way, pops next to you after a teleport). It never moves you. Only you see it; it isn't solid; skipped on Low quality. Setting: `98ish.park.pet` (per user via `userKey`).
- **Desktop toy**: a 220x240 3D Viewer 98 window with only the spinning canvas.
- **Send in Messenger**: shrinks to 15k triangles / 2 MB on the device, then uses Messenger's media path with a new kind `model` (`server/aim/media.js`, mime `model/gltf-binary`, 2 MB cap, title ≤ 40 chars, triangle count); same Blob budgets, expiry and erasers as pictures. The IM shows a card "🧊 title · N triangles · Open"; Open saves it to the receiver's `C:\My 3D` and opens the viewer.
- **Hugging Face token** (More options): optional, kept on this device (`98ish.hfToken`), sent only to Hugging Face. Anonymous ZeroGPU time is about 2 minutes a day per IP and each request reserves 120-180 s, so in practice a free token is needed for regular use.

## More free 3D time (2026-10-07, owner: "We NEED to get this to work as far as having more credits")
- **Finding:** every image-to-3D Space worth using runs on ZeroGPU, and ZeroGPU's free allowance is per person (IP when signed out, account with a token) and **shared by all Spaces**, so a fallback chain alone can't add time. What it can do: each request **reserves** its `@spaces.GPU(duration)` up front ("120s requested vs. 149s left"), and the Spaces differ a lot: TRELLIS.2 asks ~120-180 s, Hunyuan3D-2's shape step ran in ~8 s and still succeeded when TRELLIS.2 and the community TRELLIS were refused for quota ("0s left"). So the chain turns "used up" into a model most of the time, and a token gives each person their own bigger allowance.
- **Chain** (`core.js PHOTO_SPACES`, `space.js makeFromPhoto`): TRELLIS.2 (textured) -> **tencent/Hunyuan3D-2** `/shape_generation` + its own `/on_export_click` (reduce to 30k faces: the raw shape is ~500k faces / 15 MB) -> **tencent/Hunyuan3D-2.1** (same API without `caption`) -> **trellis-community/TRELLIS** `/generate_and_extract_glb` (textured) -> **VAST-AI/TripoSG** (`/run_segmentation` + `/image_to_3d`). Checked 2026-10-07 with `/api/spaces/<id>` (all RUNNING on zero-a10g) and each `/info`; **stabilityai/stable-fast-3d** answered "An error occurred" on `/run_button` and Hunyuan3D-2's `/generation_all` (textured) failed with a `NameError`, so neither is in the chain; **stabilityai/TripoSR** is in RUNTIME_ERROR. `planSpaces` puts Spaces whose `gpu` estimate fits the last known allowance first (`98ish.hfQuota`, per user, from refusals; unknown = best first). Any failure (quota, busy, asleep, worker error, no file) moves on; the status line names the Space, says why it moved on, and shows the queue (`submit(..., all_events)`: "You're 3rd in line, about 40 s"). Shape-only results are **colored from the photo** (`paint.js`: the subject's box in the photo, `subjectBox`, projected onto the model's front, `photoPixel`, as vertex colors; then GLTFExporter).
- **Token** (More options): `98ish.hfToken` per 98ish user (localStorage through the storage seam), **Check** asks Hugging Face's `/api/whoami-v2` (the only place it's sent) and says the account name; **Remove**; how-to steps in the UI and Help; forgotten by Delete My Account (`utils/account.js` ACCOUNT_KEYS with `98ish.hfQuota`); privacy topics updated (third parties: every Space in the chain; the delete-account list). More options opens by itself when a quota error shows and no token is set.
- **On-device:** not added. The smallest usable image-to-3D models (TripoSR, SF3D) need ~1-1.6 GB of weights and WebGPU/onnx kernels that don't fit an iPhone tab's memory (Floppy's brain is held to ~600 MB); revisit if a <300 MB model appears.
- **Measured end to end (real photo -> model):** Node, through the app's own `space.js` (scratchpad `snap3d/chain.mjs`, a 512 px apple photo): TRELLIS.2 refused for quota at 2.6 s, Hunyuan3D-2 shape at 11.4 s, export at 24.7 s, a 540 KB .glb (30k faces) at 26 s. In the browser at 390x844 (scratchpad `v3d.mjs`): Make 3D -> "Made in 29 s by Hunyuan3D-2, colored from your photo (TRELLIS.2 couldn't, so Hunyuan3D-2 did)", shown in the viewer (screenshot `after-viewer3d-made.png`). A TRELLIS.2 run with a token is still untimed (no token on this machine; none was committed).
