# Notifications, Web Push and Do Not Disturb
Moved from CLAUDE.md on 2026-10-05.

  - **Notification Center** (`utils/notifications.js`, taskbar bell `OS-specific/NotifyTray.jsx` + `Notify.css`, settings `NotifySettings.jsx` (lazy), `NotifyBridge.jsx` inside the Messenger provider): every toast (IMs, missed calls, Mail, Calendar, couples, game invitations, achievements, drive sync) also calls `notify({ app, title, text, key, target })`. Items merge by `key` (an IM and its push are one item), are kept per account in localStorage (`98ish.notifications`), and `target` is plain data (`{ kind: "im", with }`, `mail`, `calendar`, `program`, `invites`, `notifications`) that NotifyBridge opens. "Mark all read" / "Clear all" sync a `seenAt` per account to the server. Start > Settings > Notifications... opens the settings.
  - **Web Push** (`server/push/`, client `utils/push.js`, handlers at the end of `client/public/sw.js`): subscriptions per account and device, categories (im, calls, calendar, couples, mail, games, notes, places (Buddy Locator: shares, asks, arrive/leave)), quiet hours (calls can ring through), 404/410 subscriptions deleted. A push goes out only when the person is away from 98ish: signed off, connection gone, or the tab hidden (the client sends `aim:visibility`). Triggers: IMs (IMs to someone signed off who has push on are kept and delivered at sign on; MongoDB collections `pushsubs`, `pushprefs`, `pushinboxes`), calls (a signed-off buddy with push still rings by notification; the ring reaches them if they open 98ish while it rings; missed calls), Mail, game invitations, couple notices (letters, flowers, pair requests, quiz turns) and two schedules: calendar reminders on server calendars (every minute, deduplicated by tag `cal-rem-<fireKey>` with the in-app reminder) and Our Pet needing care (at most every 8 hours). Deep links: `/?open=im&with=NAME`, `?open=call&with=`, `?open=mail`, `?open=calendar&cal=&event=`, `?open=program&name=`, `?open=invites`, `?open=notifications` (they skip the boot screen and Welcome).
  - **iPhone:** Web Push works only for 98ish added to the Home Screen (iOS 16.4+), and the permission prompt has to come from a tap. In Safari the settings show an illustrated Add to Home Screen guide; once opened from the Home Screen they show "Turn on notifications". The manifest (`client/public/manifest.webmanifest`, standalone, icons 192/512/maskable, `apple-touch-icon` 180 in `index.html`) is what iOS needs.
  - **Do Not Disturb** (rules `utils/dndCore.js`, pure and shared with the server through a dynamic import, tests `node --test client/src/utils/dndCore.test.js`; store `utils/dnd.js` (localStorage `98ish.dnd`, per user; `useDnd()` -> `{ state, active, reason, endsAt }`, `turnOnDnd("hour"|"morning"|"off")`, `turnOffDnd()`, `setDnd(patch)`, `dndAllowsNow(kind, from)`; a 15 s tick turns the schedule and timed modes on/off); UI: the moon `OS-specific/DndTray.jsx` (desktop tray only; menu For 1 hour / Until tomorrow morning (next 07:00) / Until I turn it off / Turn Off / Settings...; shell action `dnd-settings`), `DndSettings.jsx` (lazy dialog: the switch, then More options: schedule from/to + days, "Calls from" favorites/everyone/no one, calendar reminders, Messenger Away), the bell wears a small moon (`.bellMoon`) and the Notification Center panel has the switch (`.ncDnd`; the only switch on phones), Control Panel item `dnd`, search entry `dnd`, Help `do-not-disturb`). State: `{ on, until, skip, schedule: { on, from, to, days }, calls, reminders, away, favorites, updatedAt }`; overnight schedules belong to the day they start; turning it off during the schedule sets `skip` to the schedule's end. **The one central check** is `interrupts(app, from)` in `utils/notifications.js`: `notify()` still collects everything (silently); every toast/sound/pop-up asks it first: IMs (AimContext: no bloop, no IM window popping up unless already open, no lock-screen notice; buddy door sounds), CallManager (missed-call toast/sound; an incoming ring from someone not allowed is declined quietly as a fallback), MailNotifier, CoupleOverlays (toasts + chimes), NetContext (game invitations open minimized), CalendarBridge (reminders use kind `calendar` = allowed if `reminders`; invitations/comments/changes use `calendar-activity`; reminders kept back pop up when DND ends). Clock alarms/timer, achievements and game sounds are NOT affected (your own actions, not interruptions). **Sync:** `NotifyBridge` hands the Messenger token to `setDndSession` (GET/PUT `/api/push/dnd`, newest `updatedAt` wins, also on returning to the tab), keeps `favorites` = Address Book contacts with `favorite` and a `screenName` (keys), handles Away (`DND_AWAY` message, cleared only if DND set it), and takes held pushes (`POST /api/push/held`) into the Notification Center. **Server:** `server/push` `notify()` holds (doesn't send) pushes while DND is active in the account's `tz` (calls from allowed callers and reminders if allowed still go; `system` test pushes always go; ringing pushes aren't held), up to 50 held for 7 days in `pushprefs.held`; `callAllowed(key, fromKey)`; `server/aim/calls.js` takes `allowed` and refuses a call from someone not let through with `{ ok: false, dnd: true, error: "X has Do Not Disturb on. They'll see that you called." }` plus a missed call (`dnd: true`) for the callee. Tests in `server/push/test/push.test.js` (holding, schedule across midnight/weekdays in a time zone, API newest-wins, a favorite rings / another lands in missed calls over real sockets).
