# Desktop shell and phone platform
Shared systems every program relies on: audio, dialogs, menus, phone hold menus, touch controls, the 98ish keyboard, drop-downs, user profiles, lock screen, Control Panel, accessibility, search, Help, and the simplicity pattern. Moved from CLAUDE.md on 2026-10-05.
## Shared systems
  - **Audio** (`client/src/utils/audio.js`): one AudioContext and `createBus`, following the taskbar volume and mute.
  - **Draggable dialogs** (`shared/Dialog.jsx` + `hooks/useFloating.js`). During a drag the popup follows the pointer through left/top written once per frame from a containing-block origin measured at the press (which also re-reads where the box is drawn, so nothing that moved it can cause a jump); letting go measures and moves nothing (the older translate-then-commit release snapped the box elsewhere on a real iPhone, not reproducible in Chrome or Playwright WebKit). Ends on pointerup/pointercancel/lostpointercapture (never stuck). `?dragdebug=1` (remembered per browser; `=0` off) shows an on-screen log per release: drawn before -> after -> 300 ms later, plus refits. Phones: the title bar takes the gesture (`touch-action: none`, non-passive touchstart/touchmove preventDefault, no callout/selection, no long-press menu), a second finger can't take over, a finger's press never focuses a text field (it raised the 98ish keyboard mid-drag), and the whole popup stays inside the safe areas, above the taskbar and above the 98ish keyboard (it refits when `html.kb-open`/`--kb-h` change; the keyboard no longer `translate`-lifts `[data-floating=on]` boxes, which used to jump back when it hid). Mouse dragging is unchanged (60 px of title bar kept off-edge). Browser tests: `drag-phone.mjs` (CDP touch), `drag-webkit.mjs` (Playwright WebKit iPhone 14, iOS-ordered synthetic touch pointer events: `npx playwright-core install webkit`), `drag-desktop.mjs`; each checks no snap at release, a frame later and 300 ms later.
  - **Right-click menus** (`shared/ContextMenu.jsx`, rendered into `.os-root`) and the global right-click menu (`OS-specific/GlobalMenu.jsx`).
  - **No phone "hold" menus** (`main.css` "No phone hold menus" block + `utils/touchGuard.js`, installed in `main.jsx`; test `node --test client/src/utils/touchGuard.test.js`). THE RULE: everything is `user-select: none` + `-webkit-touch-callout: none` (set on `body`; Safari needs the `-webkit-` prefixes, always write both), so a hold never shows the loupe, Copy/Look Up or Save Image. Allowed automatically: text inputs, textareas, contenteditable. Opt a reading area in with `data-selectable` (or class `selectable`); `data-selectable="mouse"` = mouse only (Messenger's transcript, where a held message opens reactions; their box has Copy); `data-selectable="false"` off again inside one; `.dialogBody p` (error/notice words) is allowed. Buttons, labels, title bars and `[role=button|menuitem|tab]` are never selectable, even inside an area. Pictures/canvases/video never offer Save Image or drag out (Photos has Save/Share menus). Opted in now: Mail text, Help topics, Address Book details, Calendar event notes/location, Notepad/WordPad, game chat and logs, Calculator display, Task Manager messages. Since iOS 18 a tap followed by a hold shows the loupe even over `user-select: none` (WebKit bug 296492), so TOUCH SURFACES cancel `touchstart`: mark an element `data-touch-surface` (or add to `SURFACE_SELECTOR`: TouchControls zones/buttons and Pickleball's court are listed there). Only on things driven by pointer events (a cancelled touchstart means no `click`) that don't scroll by dragging (Minesweeper's board scrolls, so it relies on CSS). Marked: Shred, Hover, Downhill, SPECTRA, Tetherball, Our Pet's catch game, Echo Pads, Zap It!, Boom Frenzy's field, Tetris while swiping. A finger's `contextmenu` (Android) outside fields is cancelled even if a handler only stops it. iPhones send no `contextmenu` on a hold, so app menus need `useLongPress` (Photos tiles now have it). Audit scripts `lp-audit.mjs` (WebKit, every program: styles at title bar/buttons/pictures/fields/text) and `lp-behave.mjs` (Chrome: long-press menus, Minesweeper flag, reactions Copy, touch surfaces).
  - **Touch controls** (`shared/controls/`). The editor panel takes a game's own options through the `settings` prop (exported `Check`/`Slider` match its look).
  - **98ish phone keyboard** (`shared/keyboard/`; design in `docs/keyboard.md`). Enter's label (`fields.js` `enterLabel`): the field's `enterKeyHint`, else search/url/multi-line, a dialog's default button (`data-kb-enter` from `Dialog.jsx`), Go in other forms, else Enter; never "Done" by itself. `enterKeyHint="next"` moves on without submitting. While it's up on a phone, window status bars hide (`data-kb-status="keep"` keeps one; YouTube's "Done" status read as part of the keyboard) and chat transcripts stay at the newest line. `data-kb-auto` + `requestKeyboard(el)` (`native.js`) bring it up with no tap (Speed Typist's race box at GO and when the race comes back into view). Browser scripts `kb2-*.mjs` (labels, chat/IM/Mail/dialog/game-chat layout, Speed Typist), sound on a phone `snd2-phone.mjs`.
  - **98-style drop-downs and date/time pickers** (`shared/select/`, `SelectHost` mounted once in App.jsx): takes over every `<select>` and `input[type=date|time|datetime-local|month]` with no change at the call sites. Touch: the tap's `touchend` is cancelled (no focus, so no iOS picker); a list drops down under the field like the mouse one (40px rows on phones; the owner wanted a real drop-down, 2026-10-04) and only date/time pickers open as a 98 bottom sheet (older `sel-*` scripts that wait for `.selSheet .selList` need `.selDrop .selList`); mouse: the `mousedown` is cancelled and a list/calendar drops down (date fields keep typing; only their button opens the calendar); keys: Alt+Down/F4/Space. Choices go through the native value setter plus `input`/`change` events, so React state updates. Opt out with `data-native-select`; `multiple`/`size>1` lists stay native. Tests: `select.test.js`, browser scripts `sel-*.mjs`.
  - **User profiles** (`utils/users.js`): each person on a device has their own desktop, drive, settings and scores. THE STORAGE SEAM: `userKey("98ish.x")` maps a key to the logged-on person's (`98ish.u.<id>.x`; the default user keeps the plain keys, so a device's existing data is the first user's). `utils/userStorage.js` (imported first in `main.jsx`) applies it to localStorage getItem/setItem/removeItem, so plain localStorage code needs nothing. Any other store (IndexedDB) must call `userKey()`/`keyPrefix()` itself and register `onUserRemoved(fn)`. Device keys (`GLOBAL_KEYS`: `98ish.users`, `98ish.currentUser`, `98ish.lock`...) stay shared. Switching users reloads the page (`switchUser`).
  - **Lock screen** (`utils/lock.js`, `utils/lockCrypto.js` PBKDF2-SHA256 600k with a random salt, `utils/lockTimers.js`, `OS-specific/lock/`): PIN or password per user (hash in the user's profile), Start > Lock Computer, Win+L / Ctrl+Alt+L, idle wait (`lockAfter`), screen saver (`lockOnSaver`), reopen after the wait; state in `98ish.lock` survives reloads. Wrong tries wait 5s, 15s, 45s... While locked the desktop stays mounted but hidden (`html.os-locked`), keys are stopped in lock.js, arrivals call `notifyLocked()` ("New message" only), and CallManager hands the ringing call to the lock screen (Decline at once, Answer after the PIN). "Forgot PIN?" signs in to the linked 98 Messenger screen name (`aim:verify`, no session) or, with none linked, removes the lock after a warning. Settings: Start > Settings > Passwords and Users (`applets/passwords/`). Log On (`lock/LogOn.jsx`) picks or creates users.
**Lock screen + user profiles** (not yet tried on a real iPhone): unit tests `node --test client/src/utils/lock.test.js`, server `server/aim/test/verify.test.js`, browser scripts `lock-*.mjs` (e2e, phone, idle with `page.clock`, users, forgot). Check on the iPhone: the PIN pad, the 98ish keyboard on the password box, PBKDF2 speed (~0.5 s), locking after Safari reloads the page.
  - **Control Panel** (`applets/controlPanel/`; Start > Settings, My Computer, Run `control`): a folder (`items.js`) that opens the existing settings windows plus its own applets (`programs.js` entries with `app: "cpl"` + `applet`, all in the lazy `CplApplet.jsx`): Accessibility Options, Add/Remove Programs (`hiddenDesktop`/`hiddenStart`; sizes from `program-sizes.json`, written by a build plugin in `vite.config.js`), Mouse (`doubleClickMs` via `utils/mouseOptions.js` `openOnDoubleClick`, used by `useOpenGesture`; `swapButtons`; `longPressMs` in `useLongPress`; pointer schemes/trails), Regional Settings (`utils/region.js`: 12/24h, first day, date order; the taskbar clock, Calendar's `recur.js`, Clock and Date/Time follow it), Storage (`navigator.storage` estimate/persist + localStorage breakdown), Internet Options (`ieHome`, IE history clear event), Fonts, Power Management (`keepAwake` Wake Lock in `utils/wakeLock.js`), Sounds. Magnifier (`Magnifier.jsx`) clones `.os-root` into a closed shadow root and scales it.
  - **Accessibility** (`utils/a11y.js` pure + `a11y.test.js`; `hooks/useA11y.js` puts classes/vars on `<html>`; `src/a11y.css`; `OS-specific/A11yHost.jsx`): `textSize` scales EVERY CSS font size through the PostCSS step `client/postcss-a11y.js` (6-18px and rem become `calc(Npx * var(--text-scale, 1))`; `calc(100% - 25px)` becomes `var(--title-h)`; every `@media (prefers-reduced-motion: reduce)` block also applies under `html.a11y-motion-reduce`). Opt a CSS file out with `/* a11y: fixed-text */`. High Contrast (`contrast`: black/white) recolors everything except pictures/canvases and windows with `data-hc-keep` (games, Paint, Photos; `keepsColors` in Desktop.jsx); add class `hc-keep` to keep an element's colors. For motion in JS use `reducedMotion()` from settings.js. Settings saved by older versions go through `migrateSettings`. Keyboard: Ctrl+Esc then arrows/Enter/Esc in the Start menu (`utils/startNav.js` reducer + test), Alt+F4 (TaskBar.jsx), Shift+F10/Menu key (`utils/keyboardAccess.js`), arrow keys in right-click menus, Tab/Enter on desktop icons (role=button). Windows are `role=dialog` labelled by their title; `Dialog.jsx` is `aria-modal`.
  - Tests: `node --test client/src/utils/a11y.test.js` and `startNav.test.js`; browser scripts `cp-*.mjs` (items, a11y, phone).
  - **Search everything** (Start menu box + Start > Find > Files or Folders, the `Find` program): `utils/searchCore.js` (pure: tokenize, rank, snippets, `FileIndex`, the drive indexed in memory and rebuilt only for changed items on `onFsChange`; file "Modified" dates are first-seen/changed times kept in `98ish.search.dates`), `utils/search.js` (lazy: programs + `PROGRAM_KEYWORDS` + DOS `ALIASES`, settings, files and their words, contacts, calendar events a year either side, Messenger conversations, mail headers cached by Mail in `98ish.mail.index`, photos; `openResult`), `utils/searchIndex.js` (small, eager REGISTRY: `registerSearchable([{ id, type: "settings", title, keywords, detail, icon, open: { program, extra } | { shell } | fn }])` for the Control Panel and others, `registerSearchProvider` for live data; seeded with Display tabs, Themes, Sounds, Date/Time, Keyboard, Passwords, Notifications...). UI: `OS-specific/SearchPanel.jsx` (lazy; arrows/Enter from the box, "See all results" opens Find with a tab per kind; phones: a full-screen sheet `.startArea.is-searching`), `applets/find/` (Named / Containing text / Look in / Date / Of type / Size). Returns nothing while locked. Display/Date-Time/Keyboard Properties take a `tab` window prop.
  - **98ish Help** (`applets/help/`, program "98ish Help", System Tools, Start > Help > Help Topics, Run/DOS `winhelp`, DOS `HELP TETRIS`): a Win98 HTML Help viewer (`HelpViewer.jsx`: Hide/Back/Forward/Home/Print/Options toolbar, Contents tree with arrow keys, Index with type-to-find and a Topics Found chooser, ranked full-text Search with highlighting, Favorites in `98ish.help.favorites`; phones: list, then the topic with "Back to ..."). Topics are DATA in `help/topics/*.js` (122 topics, 7 files listed in `topics/index.js`; no imports in them; format at the top of `helpCore.js`: blocks for steps, tips/notes/cautions, phone/computer, keys, tables, `{ open: "Program" }` buttons, `[[topic-id]]` links, `programs: [...]` claims). Every program must be claimed by exactly one topic (the unit test checks; add a topic when adding a program). `helpCore.js` is pure (validate, TOC, Index, Search via `searchCore`); `register.js` puts topics in the search registry as type `help` (a "Help Topics" group in Start search and Find; loaded with `utils/search.js`). Opening: `utils/help.js` `openHelp(topicId | { program } | { query })` sends `98ish:help`, App opens the window with a handoff; F1 opens the active window's program topic (not in Shred 98/Appward, which use F1); programs' Help menus start with `helpItem({ program })`; property sheets have a "?" title-bar button (`HELP_BUTTON` in Desktop.jsx); Welcome pages and program rows link to topics; Floppy offers "Open help for this program". Tests: `node --test client/src/components/applets/help/help.test.js`; browser scripts `help-e2e.mjs`, `help-phone.mjs` (every topic checked for sideways scroll at 390 px).

## Simplicity (every program; details, audit and remaining candidates in `docs/simplicity.md`)
- Each program opens to a **baseline view**: the 1-3 things most people do, in big clear controls. Nothing is removed: the rest is one tap away under a **More options Â»** disclosure with a one-line summary of what's set inside ("On this device Â· Doesn't repeat Â· Reminder 15 minutes before Â· Auto color"), in the menus, on secondary tabs, or in right-click / long-press menus. Sensible defaults make the baseline enough.
- Shared pieces: `shared/MoreOptions.jsx` (Win98 "Advanced Â»" button on a computer, a full-width row on phones; `aria-expanded`, keyboard, `forceOpen` when a problem inside needs seeing), `utils/disclosure.js` (`useDisclosure(id)`, `summarize(...)`; open/closed remembered per program part and per user in `98ish.moreOptions`), `shared/PrimaryBar.jsx` (the main action sticks to the bottom of long forms, above the home bar), `shared/GameStart.jsx` (game launchers: big Play, Play Online, More modes, Options). Same structure on a computer, which may show a little more (Camera's effects panel; the online lobby's Play with friends starts open).
- The primary action (Save, OK, Send, Start Game) is always on screen at 390x844. Phone title screens start near the top. Keep the Windows 98 look. When adding a program or option, put it in the baseline only if most people need it; update its Help topic (`more-options` explains the pattern).
- Toolbars may show a button only while it can be used (Help's Forward, IE's Stop on phones, My Computer's Cut/Copy/Delete on phones once something is selected); formatting bars sit behind **Aa** (IM window, WordPad). Every program in `programs.js` has been through this (round 2, 2026-10-04: IE, HomePage Studio, Help, WordPad, Media Player, Find, the Control Panel sheets, Quiz Show, Monster Duel, Us, Love Letters, Clock, Notifications...); the table in `docs/simplicity.md` lists what moved where.
- Tests that need a tucked-away control: press its `.moreOpts-toggle`, or preset `localStorage["98ish.moreOptions"] = '{"*":true}'` (everything nobody chose for starts open). Browser scripts `simple-*.mjs`, `simple2-apps.mjs`, `simple2-us.mjs`; unit test `node --test client/src/utils/disclosure.test.js`.
