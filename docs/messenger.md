# 98 Messenger: calls, history, pictures, voice, reactions, receipts
Moved from CLAUDE.md on 2026-10-05. Architecture basics are also in the memory note messenger-architecture.md.

## Calls
  - **98 Messenger calls** (1:1 voice/video, WebRTC): signaling in `server/aim/calls.js` (relays only between the two people in a call; busy, ring timeout, block, drop handling), ICE servers in `server/aim/ice.js`, client in `applets/aim/call/` (`engine.js` holds the call and the peer connection outside React; `CallManager.jsx` rings, opens windows, shows toasts; `CallWindow.jsx`, `RingWindow.jsx`). Calls start from the IM window header, a buddy's right-click menu, and Us ("Video call [partner]").

## 98 Messenger history, pictures, voice, reactions, receipts (2026-10-04)
- **Server** (`server/aim/`): `history.js` (store: MongoDB `imhistory`, one compact text-only doc per message `{ _id, c: "<key>|<key>" | "#<room>", p: [keys who keep it], f, fk, to, t, s (packed style, only if not default), at, u (change counter, ms*1000), x (TTL, a year), m? (media meta), r? ({ key: reaction }), h? (held) }`; `imclears` (Clear History reaching other devices), `imreads` (newest message each reader saw, per conversation); memory store without MONGODB_URI), `media.js` (`immedia` records + bytes in file sync's bucket), `conversations.js` (socket events `aim:history {since}` (0 = newest 50 per conversation + cursor; else changes, 300 a page, plus clears, reads, prefs), `aim:historyOlder`, `aim:clearHistory`, `aim:react`, `aim:read`, `aim:setPrefs`, `aim:mediaUpload/Commit/Url`). Server ids for every IM/room line (`aim:im` ack `{ id, time }`); docs are saved only for people with **Save my conversations on the server** on (user doc `prefs: { saveHistory, receipts }`, sent in `me.prefs`); turning it off pulls them from every doc (empty docs deleted). SmarterChild isn't saved on the server.
- **Caps / Atlas math**: ~250 B per doc + ~200 B of indexes (`_id`, `p+u`, `c+at`, `x`) = ~450 B/message. Newest 2,000 per pair (~0.9 MB), 1,000 per room, a year (TTL), and `IM_HISTORY_MAX_DOCS` 120,000 total (~55 MB; trimmed oldest-first, checked every 200 inserts). Reads/clears/media records are tiny. So messaging stays under ~60 MB of the 512 MB.
- **Pictures / voice** (`media.js`): client resizes to 1600 px JPEG <= 600 KB (+ a 240 px preview sent live in the IM, never stored on the server), voice = MediaRecorder AAC/MP4 where supported (iPhone) else Opus/WebM, 60 s, 40-digit waveform. `aim:mediaUpload` -> presigned PUT to Blob at `m/<HMAC of sender>/<id>` (not under `u/`, so drive's weekly tidy never touches it) -> `aim:mediaCommit` (head size check) -> `aim:im { media: { id }, thumb }` (server attaches it: only the sender's committed file; adds the recipient to `a`). `aim:mediaUrl` = presigned GET for the sender/recipients only; devices cache the bytes (IndexedDB) so each is fetched once. Budgets: `bucket.charge(cost, { scope: "media", share: 0.5 })` counts `media_adv/simple/down` in the same `blobusage` days, so media can use at most half of each free budget; `bucket.addStored(fn)` adds media bytes to the 750 MB total that drive checks too. Per account 50 MB per 90 days, all media 200 MB, 90-day expiry (upkeep every 30 min deletes objects + records; the message shows "expired"). No bucket or a used-up budget -> `{ resting }` -> client line "Picture couldn't be sent: online storage is resting" (texts unaffected). Each picture costs 1 advanced op (put) + 1 simple (head) + 1 simple + bytes per first view per device.
- **Client** (`applets/aim/history/`): `historyCore.js` (pure, `historyCore.test.js`: merge by id, reactions, the "Read 10:42 PM" / "Delivered" / waiting line, waveform, voice type, failure text), `historyDb.js` (IndexedDB `98ish-im` (+ `-<user id>`), stores `msgs` (pk `acct|id`, index [acct, ck, time]), `meta` (cursor, reads), `media` (Blobs, newest 400); `eraseAccount(acct)` used by `utils/account.js`; `onUserRemoved` deletes the db), `mediaClient.js` (prepare/upload/fetch/record/play through `masterOutput`), `ImExtras.jsx` (+ `history.css`: PictureBubble, VoiceBubble, PictureViewer with Save to My Pictures, ReactionPicker (portal, not `.window`: phones make every `.window` full screen), ReactionChips, PicturePicker (My Pictures grid, device upload, `capture` camera on touch), VoiceBar (hold to talk; quick tap = tap-to-start + Send)). `AimContext`: `syncHistory()` on sign on/resume (5 s overlap on the cursor), `loadConvo`/`loadRoom` when a window opens, `loadOlder` on scroll-to-top (device first, then `aim:historyOlder`), `sendIm` (temp id -> server id/time), `sendMedia`, `react`, `markRead` (IM window active + not minimized + page visible + focused; once per message), `clearHistory`, `setServerPrefs`; events `aim:react`, `aim:read`, `aim:delivered`, `aim:accountGone` (local copy renamed to "(deleted account)"). Conversations key by `ck` (other person's key or `#room`). Search ("messages" provider) reads the device copy.
- **UI**: IM window baseline unchanged + one **+** (Picture... / Voice Message); reactions by long-press/right-click; "Read"/"Delivered" line under your last message; **More »** gains Clear History; chat rooms: reactions + Clear History beside the people list. My AIM > **Preferences...** = Sounds, Save my conversations on the server, Read receipts (off = you neither send nor see them). Help topic `messenger-history`; privacy topics updated.
- **Delete My Account**: eraser steps `messages` (their copies go; the other person's copy stays with sender/recipient "(deleted account)" and the conversation renamed `<partner>|~<random>`, so a new owner of the name sees nothing; room lines anonymized; reactions/reads/clears go) and `im media` (deleted unless a recipient can still see it: then `k: ""` until expiry; their access to received media removed).
- **Tests**: `server/aim/test/history.test.js` (store caps/cursors/recent/older/clear/forget/reads/erase+anonymize, sockets: ids, catch-up, reactions, receipts + opt-out, saving off, rooms, Delivered via a fake push, media against the fake Blob: signed upload, size check, access, scoped budgets, quota, no bucket, expiry, erase), `server/account/test/delete.test.js` (messages + im media steps); `node --test client/src/components/applets/aim/history/historyCore.test.js`. Browser (scratchpad, vite 5382, server 8382 with `BLOB_READ_WRITE_TOKEN=vercel_blob_rw_teststore_secret VERCEL_BLOB_API_URL=http://127.0.0.1:9382/api/blob BLOB_STORE_URL=http://127.0.0.1:9382/store`, fake blob `node server/drive/test/fakeBlob.js 9382 vercel_blob_rw_teststore_secret`; Chrome with fake media flags; CDP `Emulation.setFocusEmulationEnabled` so `document.hasFocus()` is true): `msg-e2e.mjs` (phone + desktop chat, Read, reactions both ways, receipts off, reload both, second device catch-up, picture with signed PUT/GET + full view 1600 px + Save to My Pictures, voice message hold/send/play), `msg-privacy.mjs` (Clear History, saving off/on, Delete My Account: local erase, partner's copy anonymized locally and on the server, a new owner of the name sees nothing), `msg-resting.mjs` (server without Blob: "Picture couldn't be sent: online storage is resting", text still works). A long press ends with a click the long-press hook swallows for 600 ms: wait before the next tap in tests.
- **Not yet**: tried on a real iPhone (MediaRecorder AAC, `capture` camera, long-press vs text selection); Delivered is only browser-untested (needs push); conversations with a deleted account are kept but there's no list to open them (Find shows them); room history is only for people who were in the room.

## "Meet me at <venue>" cards (2026-10-08)
- **What:** in an IM, **+** > **Meet Me at a Court...** lists Pickleball 98's real venues (My Park stars first) and up to 8 Venue Finder courts kept in Pickleball 98's prefs (`parkPlaces`), then **Send**. The buddy sees a small card (📍 **Meet me at Los Cab Sports Village**, the town) with **Play here** (Pickleball 98 opens My Park at that venue: handoff `{ meet: { venue, place? } }`, a Venue Finder court is kept like one you picked so My Park can build it) and **Directions** (`openMaps({ name, lat, lon, address, directions: true })`, from the tap). IMs only (not chat rooms, not SmarterChild). No new top-level button: it lives in the existing **+** menu.
- **Card:** `{ k: "venue", id, n, lat, lon, a?, c?, sh? }` built by `pickleball/play/meet.js` (`realCard` from `park/venues/index.js` VENUE_LIST + Real Games' street addresses in `pbclub/clubCore.js`; `finderCard` for kept Venue Finder courts). Nothing about the sender's location.
- **Server** (`server/aim/cards.js` `cleanCard`): `aim:im { card }` is checked field by field: kind `venue` only, id `[a-z0-9]{1,24}`, name 1-60 chars (control characters and runs of spaces collapsed), lat/lon finite and on Earth (rounded to 6 decimals), address <= 120, town <= 40, shard `[a-z0-9]{1,12}`, unknown fields dropped, at most 400 bytes; anything else -> `{ ok: false, error: "That card can't be sent." }` and nothing is relayed. A card can't ride with a picture, and SmarterChild refuses it. Kept on the history doc as `v` (`toWire` -> `card`), so a second device and a reload show it; push/Notification Center text "📍 Meet me at <venue>" (`cardPreview`, client `previewText`). Atlas: one extra ~150-250 B field on a message that's already capped (2,000 per pair, 120,000 total); the `messages` eraser step already removes it with the message. No new store, no new eraser step.
- **Client:** `AimContext` `sendCard(screenName, card)` (through `sendIm`, so pending/failed/ids work the same), `openVenue(card)`; `historyCore.fromServer` keeps a card that has the shape; `MessageText` draws `.aimVenueCard` (`data-venue-card`, `data-venue-play`, `data-venue-directions`); `ImWindow` `MeetPicker` (`data-meet=<id>`).
- **Tests:** `node --test server/aim/test/cards.test.js` (field checks, tidying, size, refusals; sockets: live delivery, with text, saved + catch-up, bad cards never reach the buddy, not with a picture, not to SmarterChild); `node --test client/src/components/applets/pickleball/play/meet.test.js` (every real venue's card passes the server's check unchanged, Venue Finder cards, the list order, Play here handoffs, Directions, fromServer/previewText). Browser (scratchpad `r8meet.mjs`, vite 5303 + server 8303, two iPhone-sized contexts, swiftshader): + menu > Meet Me at a Court..., the list, Send, Bob's IM opens with the card, no sideways scroll, Directions opens Maps 98 on Los Cab with its address, the card is still there after a reload, Play here opens My Park loading Los Cab (10/10). Screenshots `shots/r8-meet-*.png`.

## Passkeys (wave 4, 2026-10-08)
- **What:** "Sign On with a passkey" on the Sign On window (no screen name typed: discoverable credentials) and **My AIM > Passkeys...** (also Control Panel > Passwords > 98 Messenger account): list (name from the device, "synced" when backed up, added / last used), **Add a passkey...** (password again, then a second tap on **Create Passkey**), **Remove...** (up to 10 per account). The password keeps working; a passkey is another way in.
- **Why two taps / options fetched ahead:** iOS Safari only opens Face ID from a user gesture, and a socket round trip loses it. The Sign On window asks `aim:passkeyOptions` when it shows (and every 4 minutes); the tap calls `navigator.credentials.get()` at once. Adding: the password check returns the creation options, then the Create Passkey tap calls `create()`.
- **Server** (`server/aim/`): `webauthn.js` (no library; CBOR reader, authenticator data parser, COSE -> JWK -> `crypto.createPublicKey`, ES256 (DER), RS256 (PKCS#1 v1.5, 2048-4096 bit), EdDSA; registration: type `webauthn.create`, challenge (timing-safe), exact origin, `crossOrigin` refused, rpIdHash, UP + UV required, AT, credential id = authData's, the key on the curve, attestation `none` (statement ignored, `none` must be empty); sign on: type `webauthn.get`, challenge, origin, rpIdHash, UP + UV, userHandle matches, signature over authData + SHA-256(clientDataJSON), the key's type must match its stored alg, counter must go up unless both are 0 (synced passkeys send 0)), `passkeys.js` (ceremonies: 32-byte challenges in memory for 5 minutes, used once (taken before checking), tied to the origin and (adding) the account; at most 2,000 waiting; random 16-byte user handle per account, never the screen name; excludeCredentials; 10 per account), `passkeyStore.js` (MongoDB `aimpasskeys`: `{ id, key, userHandle, rpId, alg, jwk, counter, backedUp, transports, name, createdAt, lastUsedAt }`, a few hundred bytes each: 10 x 2,000 accounts would be ~6 MB of Atlas at most; memory without MONGODB_URI). Socket events in `index.js`: `aim:passkeyOptions` (anyone; 30/min per IP), `aim:signOnPasskey { challengeId, credential, remember }` (same answer as `aim:signOn`; a failure counts toward the 20-per-5-minutes failed sign-on limit per IP; a deleting account is refused), `aim:passkeyAddStart { password }` (signed on; bcrypt check with the failed-try limits), `aim:passkeyAdd`, `aim:passkeyList` (`available`: this origin can use passkeys), `aim:passkeyRemove`.
- **RP ID and origin:** the socket handshake's `Origin` picks the RP: `https://98ish.vercel.app` -> RP ID `98ish.vercel.app` (vercel.app is a public suffix, so it can't be shorter); `http(s)://localhost:<port>` -> `localhost` (dev); anything else (Vercel previews, `127.0.0.1`, other sites) gets "Passkeys aren't available on this copy of 98ish". The clientData origin must equal that origin, and each record keeps its rpId (a localhost passkey never works in production and the other way round). `WEBAUTHN_ORIGINS` (comma list) replaces the production list; `WEBAUTHN_LOCALHOST=0` turns localhost off (`docs/env-vars.md`). Production needs neither.
- **Client:** `utils/passkeys.js` (base64url, options -> `PublicKeyCredential*Options`, credential -> JSON, friendly errors, `deviceName()`), `AimContext` `passkeyOptions`/`signOnPasskey`/`openPasskeys`, `SignOn.jsx` (button `data-passkey-signon`, hidden where the server says passkeys aren't available), `Passkeys.jsx` (window app `aim-passkeys`; in Floppy's `NEVER_APPS`; private to Come Over like every `aim*` app).
- **Delete My Account:** eraser step `passkeys` (every record of the account; inventory line in `server/account/index.js`). The passkey itself stays in the device's password manager, where it no longer opens anything; Delete My Account's list and Help say so.
- **Security notes:** only public keys are stored; no passwords or secrets go through the passkey path; a stolen session can't add a passkey without the password; replay = same challenge (gone) or an old assertion (challenge mismatch); a cloned authenticator with a counter is caught; the user handle is random so an authenticator never learns more than the screen name it shows. Not done: attestation (any authenticator is accepted, by design), PRF/E2EE key wrapping (round2.md), conditional UI (autofill) sign on.
- **Tests:** `node --test server/aim/test/webauthn.test.js` (CBOR incl. junk; ES256/RS256/EdDSA register + sign in with a software authenticator `test/softAuthenticator.js`; refused: wrong origin (incl. look-alike and http), wrong/replayed/expired challenge, wrong type, cross-origin, other website, no presence, no Face ID check, credential id swap, unsupported alg, point off the curve, non-empty "none" attestation, bad signature, another key's signature, counter not going up, another account's user handle, a key stored under another alg; RP rules; service: one-time challenges tied to account and origin, localhost vs production, caps, list without keys, remove only your own, erase, pending bound; sockets: password again, add, list, sign on with remember, replay on another socket, another origin refused, Delete My Account erases them). Browser (scratchpad `wave4-desktop.mjs`, vite 5304 + server 8304): Chrome's virtual authenticator (CDP `WebAuthn.addVirtualAuthenticator`, ctap2 internal, resident keys, UV): Get a Screen Name -> My AIM > Passkeys... -> add (discoverable, rpId localhost) -> Sign Off -> Sign On with a passkey -> signed on, counter up.
- **Checking production after a deploy:** (1) on https://98ish.vercel.app sign on, My AIM > Passkeys... should show **Add a passkey...** (not "Passkeys work on https://98ish.vercel.app"; that would mean the Origin header didn't match: check `WEBAUTHN_ORIGINS` on Render isn't set to something else); (2) add one on an iPhone (Face ID sheet names "98ish.vercel.app"), Sign Off, then **Sign On with a passkey**; (3) Settings > Passwords on the iPhone lists it under 98ish.vercel.app; (4) Remove it in Passkeys... and check signing on with it says "isn't linked to a 98 Messenger account any more". Render logs show nothing about passkeys unless something throws.
